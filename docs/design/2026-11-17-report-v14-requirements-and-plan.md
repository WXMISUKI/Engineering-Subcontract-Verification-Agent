## 0 结论先行

1. 三篇样例不是三种模板，而是**同一种“建设单位审查意见”的三种详略程度**。建议做**一版 V1.4 + 三档详略**，而不是再做三版模板。
2. 样例的强项是“结论先行、问题具体、补正明确”，V1.3 的强项是“维度覆盖、证据可追溯、状态可审计”。V1.4 应该是两者的**合并**，不是替代。
3. 8 张附表应作为一个**独立附件**（附件：分包合同合规审查表），与正文同源生成；**不能沿用表内预填的“符合”**，必须按当前任务动态填“符合/不符合/缺项/—”。
4. 建议方案 A：新增 V1.4，保留 legacy 与 V1.3，模板选择按“用途”而不是“版本号”展示。这样风险最低，也最符合当前交接状态。

## 3 三篇样例 vs V1.3：到底差在哪

| 维度 | 样例 1（桩基专业分包） | 样例 2（吊装劳务分包） | 样例 3（吊装专业分包） | V1.3 |
| --- | --- | --- | --- | --- |
| 体裁 | 建设单位审查意见 | 审查结论 + 专题 + 签批 | 建设单位审查意见 | AI 初审报告 |
| 开头 | 工程/分包/金额 | 总体审查结论 | 事项/范围/程序 | 致 + 首段 |
| 主体结构 | 6 个主题 | 7 个主题 | 5 个主题 + 5 条要求 | 六段固定 |
| 问题呈现 | 嵌在主题里 | 重点问题 + 补正清单 | 少量要求 | 第四部分单列 |
| 结论 | 原则同意附条件 | 原则同意附条件 | 同意 | 人工填写 |
| 证据 | 证书号、社保月份 | 金额差异、社保断缴、设备数量 | 资质、人员 | 附件二逐条 |
| 附件 | 无 | 补正清单 | 无 | 附件一 + 附件二 |
| 语气 | 建设单位对总包 | 建设单位对总包 | 建设单位对总包 | 系统对总包 |
| 适合读者 | 领导/建设单位 | 建设单位/总包 | 领导/建设单位 | 审查人 |

### 3.1 三个关键差异

1. **结论位置不同**：样例把结论放在最前（或最后签批），V1.3 放在第五部分。领导阅读习惯是“先看结论，再看依据”。
2. **问题颗粒度不同**：样例直接写“安许 2026-04-16 到期”“金额差 1.16 万”“社保 2025.09–2026.07 断缴”，V1.3 的问题事实更概括。样例更接近用户想“精准把握问题”的诉求。
3. **附件定位不同**：样例 2 的“资料补正清单”是行动清单；V1.3 的附件二是问题清单。8 张附表正好可以作为“检查表 + 补正表”的合体。

### 3.2 不能直接照搬的地方

| 样例内容 | 风险 | 处理 |
| --- | --- | --- |
| “原则同意 / 同意 / 附条件通过” | 属审批结论，机器不能替人决定 | 系统出“建议结论”，人工审批栏留白或确认 |
| 具体人名、证书号、金额、日期 | 样例事实，不是当前任务事实 | 全部动态绑定当前任务 |
| “总监签字”“建设单位（章）” | 签署事实不能伪造 | 只保留签字/盖章位 |
| 样例 2 的“金额差 1.16 万” | 需要精确计算，样例可能算错 | 由系统按原文金额重算，不能抄 |
| 附表预填“符合” | 表单默认值，不是结论 | 动态填“符合/不符合/缺项/—”，无依据填“—” |

## 4 角色与交互设计（架构师 / 项目经理视角）

### 4.1 四类读者，四种默认视图

| 角色 | 最关心 | 默认视图 | 不该看到 |
| --- | --- | --- | --- |
| 建设单位领导/审批人 | 能不能过、有什么风险、要谁补什么 | 结论卡 + 3–5 条关键问题 + 签批 | 逐条证据、OCR 细节 |
| 监理/审查人 | 哪条规则命中、证据在哪、是否误判 | 问题队列 + 证据 + 维度覆盖 | 大段叙述 |
| 总包/分包 | 要补什么、什么时候补、找谁 | 补正清单 + 期限 + 责任单位 | 内部规则编号、模型细节 |
| 系统管理员 | 模板/规则版本、历史快照 | 版本与审计信息 | 业务结论 |

### 4.2 报告页建议布局

```
┌─────────────────────────────────────────────┐
│ 结论卡：建议结论 | 风险 3 | 待补正 5 | 审批状态 │
│ [导出 Word] [导出 PDF] [审阅版/详细版]         │
├──────────────┬──────────────────────────────┤
│ 主题导航      │ 正文（结论先行 + 主题叙述）      │
│ 资质与主体    │ 1. 资质与承接能力               │
│ 人员与持证    │ 2. 安全生产许可                 │
│ 范围与清单    │ 3. 人员配置                     │
│ 合同与计价    │ ...                            │
│ 安全质量工期  │ 问题卡片：事实/证据/补正/责任     │
│ 报审与补正    │                                │
│ 综合结论      │ [查看证据] [查看原文页码]        │
├──────────────┴──────────────────────────────┤
│ 附件：分包合同合规审查表（1–8 表，可折叠）      │
└─────────────────────────────────────────────┘
```

### 4.3 减负原则

1. **结论先行（BLUF）**：首屏必须回答“能不能过、卡在哪、补什么”。
2. **渐进披露**：默认只显示结论和关键问题；依据、证据、页码折叠。
3. **单一事实源**：正文、附表、导出三处数字一致，不重复计算。
4. **状态不超过四态**：符合 / 不符合 / 缺项 / —；不要再加“基本符合”“待核实”等。
5. **机器与人工分开**：机器结论用中性标记，人工审批用独立区域，不能混写。
6. **按用途命名模板**：不要用“V1.3 / V1.4”让用户选，改成“正式审查意见（领导审阅）/ 详细核查报告（审查人）/ 历史五阶段”。

## 5 三个方案与推荐

### 方案 A：新增 V1.4，保留 legacy 与 V1.3（推荐）

- V1.4 = 叙事正文（样例风格）+ 8 表合并附件。
- V1.3 = 详细核查报告（八维度 + 附件一/二），继续给审查人用。
- legacy = 历史兼容，不再新增功能。
- 模板选择按用途命名，默认正式输出走 V1.4。

**优点**：风险最低、历史不变、满足领导样例需求、可逐步收敛。
**缺点**：短期三套模板并存，需要清晰的用途标签。
**适用**：当前交接状态和未验收状态。

### 方案 B：用 V1.4 替换 V1.3

- 只保留 legacy + V1.4，V1.4 同时承担叙事和详细核查。
- 8 表附件替代 V1.3 附件二。

**优点**：用户只面对两套，长期更干净。
**缺点**：要迁移 V1.3 历史快照和前端组件；八维度表要么并入附件，要么丢失；风险高。
**适用**：用户明确不要 V1.3 时。

### 方案 C：只改导出，不改页面

- 页面仍显示 V1.3，Word/PDF 导出 V1.4 叙事版。

**优点**：开发量最小。
**缺点**：预览与导出不一致，用户会困惑；不推荐。

### 推荐

**先做方案 A**，用 V1.4 满足样例需求；等真实材料验收后，再评估是否收敛为方案 B。

## 6 V1.4 结构与 8 表附件设计

### 6.1 V1.4 正文结构（建议）

```
标题：{工程名称}{分包事项}分包审查意见
抬头：致：{施工总承包单位}／项目部
结论卡：建议结论 | 风险数 | 待补正数 | 审批状态

一、审查范围与依据
二、资质与主体合规性
三、人员配置与持证
四、分包范围与负面清单
五、合同与计价边界
六、安全、质量、工期与工资保障
七、报审程序与资料补正清单
八、审查结论与要求
落款：审查人/复核人/签发人（留白）+ 日期
附件：分包合同合规审查表（1–8 表）
```

说明：

- 章节不是固定八段，而是按任务实际有内容的主题出现；没有内容的主题省略，避免“凑段落”。
- 每条问题卡包含：事实、证据（材料/页码/引文）、判定、补正要求、责任单位。
- 结论区分为“系统建议结论”和“人工审批结论”，后者留白或由人工确认。

### 6.2 8 表合并附件结构

```
附件：分包合同合规审查表
一、分包合法性审查        → 4 列表格
二、现场管理机构与人员锁定审查 → 4 列表格
三、价款、计量与审计审查   → 4 列表格
四、质量、安全、环保与保修审查 → 4 列表格
五、工期与违约责任审查     → 4 列表格
六、农民工工资与信用管理审查 → 4 列表格
七、报审材料清单（开工前置核查） → 4 列表格（序号/材料/是否齐全/备注）
八、综合审查结论          → 键值块（结论/红线/期限/责任人）
```

处理规则：

| 表内字段 | 动态来源 | 缺值处理 |
| --- | --- | --- |
| 审查项 | 附表固定目录 | 固定 |
| 符合/与否 | 当前 finding/规则结论 | 无依据填“—”，不填“符合” |
| 审查要点 | 附表固定说明 | 固定 |
| 审查意见/修改建议 | 当前问题事实 + 补正要求 | 无问题填“本次未发现异常”，不写“符合” |
| 是否齐全（表 7） | 材料台账 | 是/否/无法核实 |
| 综合结论（表 8） | 系统建议 + 人工填写 | 人工栏留白 |

### 6.3 与 V1.3 的关系

- V1.4 不复用 V1.3 的八维度表作为正文，但**复用同一套 finding/维度/证据数据**。
- V1.3 的附件一/二保留在 V1.3；V1.4 使用 8 表合并附件，两者不混排。
- 两版共享 `template_id / template_version / 内容哈希 / 规则版本` 审计字段，但历史快照各自冻结。

## 8 风险与不做的事

| 风险/不做 | 说明 |
| --- | --- |
| 不做三套独立模板 | 三篇样例是详略差异，不是三种体裁 |
| 不把样例结论写死 | “原则同意/同意”必须人工确认 |
| 不用附表预填“符合” | 必须动态判定；无依据填“—” |
| 不让模型自由写正文 | 正文由规则事实 + 模板句式投影，模型只做措辞辅助 |
| 不重复计算数字 | 正文、附表、导出共用一个投影 |
| 不改核查规则 | 本轮只改报告呈现，不改 A1/A2/A3 判定 |
| 不重跑真实任务 | 未经授权不调用付费模型/OCR、不重启部署 |
| 不覆盖历史 | V1.3 历史快照保持只读 |

## 9 已确认决策

| 决策 | 结论 |
| --- | --- |
| 模板策略 | 新增 V1.4，保留 legacy 与 V1.3 |
