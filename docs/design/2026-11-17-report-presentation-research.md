# 核查报告展示方式调研与 V1.4 重构建议

日期：2026-11-17。状态：**调研与设计建议**，未改代码。

背景：真实测试后，V1.4 阅读效果不如 V1.3。V1.3 至少能用八维度矩阵快速看清“哪一维有问题”，V1.4 变成了一张很长的缺项表，叙述也没有样例的清晰度。

---

## 0 结论先行

1. **V1.4 的问题不是“排版不好看”，而是把两类东西混在了一起**：
   - 总结性问题（领导要看的 3–7 条风险）；
   - 检查性问题（审查人要逐项核对的几十条检查项）。
2. **市面成熟做法是分层**：结论摘要 → 模块结论 → 例外问题 → 检查表附件。不是把所有检查项塞进正文。
3. **V1.4 应该吸收 V1.3 的矩阵，而不是丢掉它**：
   - V1.3 的八维矩阵负责“一眼看清覆盖和状态”；
   - 样例的函件叙述负责“领导能读懂”；
   - 例外问题清单负责“审查人能补正”；
   - 8 表附件负责“逐项留痕”。
4. **段落格式应按“结论 + 已核实事实 + 确证问题 + 待核实 + 补正”五段式写**，每个模块一段，不做成表格堆叠。

---

## 1 为什么 V1.4 反而不如 V1.3 清楚

| 原因 | V1.3 | V1.4 当前 |
| --- | --- | --- |
| 结构 | 八维度矩阵，一眼看到每维状态 | 长问题表 + 薄叙述 |
| 问题分层 | 维度状态 + 问题清单 | 总结性问题和检查性问题混在一张表 |
| 已核实事实 | 维度摘要能看到“已形成 N 项结论” | 只写“缺 XX”，看不到已核实内容 |
| 文本质量 | 维度/条目有固定结构 | 大量重复的“报审资料缺 XX” |
| 读者负担 | 审查人可以逐项看 | 领导要在一堆缺项里找重点 |
| 结论 | 总体意见按状态列维度 | 顶部“建议结论”与问题数量不匹配 |

**一句话**：V1.3 清楚是因为它有“矩阵 + 状态”；V1.4 不清楚是因为它只有“问题表”，还混入了大量未核实/误判内容。

## 2 市面成熟做法

### 2.1 审计发现的 5C 结构

内部审计和外部审计普遍用 5C 组织一条发现：

| 要素 | 回答的问题 | 对应我们的字段 |
| --- | --- | --- |
| Criteria 标准 | 应该是什么 | 法规/细则/合同条款/负面清单 |
| Condition 事实 | 实际是什么 | 材料原文、证书号、有效期、金额、社保月份 |
| Cause 原因 | 为什么会这样 | 缺材料、未审批、人员未到岗、合同未约定 |
| Consequence 影响 | 为什么重要 | 不得进场、不能计量、存在转包/违法分包风险 |
| Corrective action 补正 | 谁来做什么、何时完成 | 补交材料、重新报审、更换人员、解除合同 |

**对我们的启发**：现在报告里的“问题事实 + 判定理由 + 补正要求”其实就是 5C 的碎片，但没有按 5C 组织，所以读起来散。应该把一条问题写成“事实—依据—影响—补正”四行，而不是三个列。

### 2.2 例外报告（Exception Reporting）

成熟合规系统只报“例外”，不逐条罗列所有通过项。关键做法：

- 例外标准要事先定义，不能凭感觉；
- 例外要分严重度、责任人和期限；
- 例外要记录根因和影响；
- 通过项只给数量，不逐条展开。

**对我们的启发**：问题表只放“确证不符合/缺项”；“待核实/未覆盖”单独放，不能和例外混在一起。

### 2.3 合规驾驶舱

合规驾驶舱通常包含：

- 总体状态（红/黄/绿）；
- 按模块的覆盖率和问题数；
- 未关闭问题、逾期问题；
- 证据状态；
- 下钻到模块和条目。

**对我们的启发**：报告第一页应该是“驾驶舱”，不是“问题表”。八维度/六模块的矩阵就是我们的驾驶舱。

### 2.4 国内工程检查表

国内工程检查表普遍是：

```
检查项目 | 序号 | 检查内容 | 检查结果（符合/不符合） | 检查情况描述
```

**对我们的启发**：8 表附件本身是对的，问题在于它不该占据正文。它是“检查表附件”，不是“审查意见正文”。

### 2.5 可借鉴与不可照搬

| 做法 | 借鉴 | 不照搬 |
| --- | --- | --- |
| 5C | 每条问题按事实/依据/影响/补正写 | 不要求每条都写根因分析，太重 |
| 例外报告 | 只报例外，通过项给数量 | 不把“未核实”当例外 |
| 合规驾驶舱 | 模块状态 + 数量 + 下钻 | 不做复杂图表，报告以文字为主 |
| 国内检查表 | 8 表附件逐项留痕 | 不把检查表当正文 |

## 3 分包审查的展示模型

### 3.1 四层结构

```
L1 结论摘要（1 页）
  - 核查结果：不符合/缺项/待核实数量
  - 模块状态矩阵（6–8 个模块，红/黄/灰）
  - 3–5 条关键风险
  - 审查范围与方法

L2 模块结论（每个模块 1 段）
  - 一句结论
  - 已核实事实
  - 确证问题（如有）
  - 待核实事项（如有）
  - 补正要求（如有）

L3 例外问题清单（只列确证问题）
  - 按严重度/模块分组
  - 每条：事实 / 依据 / 影响 / 补正 / 责任单位

L4 附件
  - 8 表检查表
  - 证据页码/原文引用
```

### 3.2 两类问题分开

| 类型 | 数量 | 读者 | 展示位置 | 格式 |
| --- | --- | --- | --- | --- |
| 总结性问题 | 3–7 条 | 领导/建设单位 | L1/L3 | 风险卡：事实+影响+补正 |
| 检查性问题 | 几十条 | 审查人/总包 | L2/L4 | 模块段落 + 检查表 |

**规则**：

- 总结性问题只从“确证不符合/关键缺项”中提炼，不把待核实算进去；
- 检查性问题只在对应模块展开，不重复写进总结；
- 通过项只写“已核查 X 项”，不逐条列；
- 未核实/未覆盖单独列，不混入问题表。

### 3.3 状态体系

| 状态 | 含义 | 展示 |
| --- | --- | --- |
| 通过 | 有证据，规则命中“符合” | 绿/正常 |
| 不通过 | 有证据，规则命中“不符合” | 红/风险 |
| 缺项 | 确认缺适用材料 | 黄/待补 |
| 待核实 | 材料不足/冲突/未定位 | 灰/待处理 |
| 不适用 | 本次分包类型/范围不适用 | 灰/不适用 |
| 未覆盖 | 本版本无自动规则 | 灰/人工 |

**禁止**：没有证据写“通过”；没执行写“通过”；未覆盖写“待核实”混过去。

### 3.4 模块划分

按分包审查的实际模块，建议 6 个正文模块 + 2 个辅助模块：

| 正文模块 | 对应检查内容 |
| --- | --- |
| 1 资质与主体 | 营业执照、法人、资质类别/等级、类似业绩、内部信用 |
| 2 安全生产许可 | 安许证号、许可范围、有效期、续期 |
| 3 人员配置与持证 | 项目经理/总工/安全员/质量员、证书、劳动合同、社保、特种作业 |
| 4 分包范围与负面清单 | 分包内容、负面清单、关键工序、再分包/转包 |
| 5 报审程序与合同计价 | 报审材料、签字链、合同文本、计价、支付、违约 |
| 6 质量安全、工期与工资 | 质量目标、安全协议、工期节点、工资专户/代发 |

辅助模块：

- 设备与资源（有材料才展开）；
- 信用与外部核验（只有内部材料才写）。

## 4 段落格式模板

### 4.1 通用五段式

每个模块按下面顺序写，段落之间不空转：

```
【结论】一句话，明确通过/不通过/缺项/待核实。
已核实：[证书/人员/合同/金额等具体事实]。
问题：[确证问题，事实+依据+影响]。
待核实：[材料不足/冲突/未定位，写清缺什么]。
补正：[具体动作+责任单位+期限]。
```

### 4.2 资质与主体

```
【结论】资质与主体合规，未发现不符合项。
已核实：分包人持有地基基础工程专业承包一级资质，证书编号 ××，有效期至 ××；
营业执照统一社会信用代码 ××，法人资格有效；资质类别覆盖桩基、基坑围护、地基处理。
问题：无。
待核实：无。
补正：无。
```

有问题的写法：

```
【结论】资质等级与分包内容不匹配，需补正后复核。
事实：分包内容为桩基工程，分包人持有 ×× 资质，等级 ××；对照《建筑业企业资质标准》，
      该资质承包范围不含 ××。
影响：不满足单位工程专业承包资质要求，不得进场。
补正：分包人补交覆盖本工程范围的资质证书；承包人复核后重新报审。
```

### 4.3 安全生产许可

```
【结论】安全生产许可证已过期，不符合进场条件。
事实：证书号（沪）JZ安许证字〔××〕××，许可范围“建筑施工”，有效期至 2026-04-16；
      本次核查基准日 2026-11-17。
依据：《上海市公路工程施工分包管理实施细则》附件 3 第 2 项。
影响：证照不在有效期，不得进场施工。
补正：分包人补交续期后的安全生产许可证；未补正前不得签发开工令。
```

### 4.4 人员配置与持证

```
【结论】关键岗位基本齐全，但安全员社保断缴。
已核实：项目经理 ××（注册建造师、交安 B），总工 ××（交安 B、工程师），
        专职安全员 ××（交安 C）；质量、施工、资料、材料、机械、劳务、标准员已配备。
问题：安全员 ×× 社保 2025.09–2026.07 断缴，不能证明为本单位人员。
依据：《实施细则》附件 3 第 3 项（劳动合同、近一个月社保缴费证明）。
影响：不满足“主要管理人员为本单位人员”的要求。
补正：补缴社保并出具连续参保承诺；或更换符合条件的安全员。
```

### 4.5 分包范围与负面清单

```
【结论】分包范围不在负面清单主体/关键工作内，但桥梁桩基关键工序需确认。
已核实：分包内容为预制构件吊装，属于专业化施工内容；未发现整体转包、肢解分包。
问题：本次分包涉及桥梁桩基，是否属于桥梁工程关键工序，现有材料未明确。
影响：如属于主体结构核心受力部位，应由总承包单位自行施工或另行专项说明。
补正：承包人出具桥梁桩基是否属于关键工序的书面说明；必要时调整分包范围。
```

### 4.6 报审程序与合同计价

```
【结论】报审材料基本齐全，但合同文本不完整，计价与支付条款无法核对。
已核实：报审包包含合同、资质、安许、人员名单和社保记录；签字链有项目经理、
        专业监理工程师签字。
问题：仅附清单合价，未附完整分包合同条款；未见总监理工程师签署日期。
影响：计价口径、进度结算、农民工工资支付、违约条款无法审查。
补正：补交完整分包合同（含计量周期、结算办法、工资专户、违约条款）；
      补签或提供总监理工程师签署页。
```

### 4.7 质量安全、工期与工资

```
【结论】本版本未建立完整自动核查，以下事项需人工核查。
已核实：合同约定质量目标、安全协议、工期节点（如材料可见）。
待核实：质量目标是否不低于总包合同；安全文明施工费是否单列；
        工资专户、实名制、总包代发是否落实；关键节点是否与总体施组一致。
补正：承包人补充上述材料，监理复核后报建设单位备案。
```

### 4.8 设备与资源（条件展开）

```
【结论】设备清单与吊装规模不匹配，需补报。
已核实：已报 1 台电焊机；汽车吊/履带吊由甲方提供（如合同约定）。
问题：未见汽车吊/履带吊、路基箱、探伤配合、测量仪器、应急设备清单及检验证书。
影响：无法证明满足吊装工艺要求。
补正：补报设备清单、权属/租赁证明、检验证书；甲方提供设备需注明。
```

## 5 页面布局与交互

### 5.1 报告页

```
┌─────────────────────────────────────────────┐
│ 标题 / 工程 / 分包单位 / 金额                │
│ 核查结果：不符合 2｜缺项 3｜待核实 5          │
│ 模块矩阵：资质 ✅ 安许 ❌ 人员 ⚠ 范围 ✅ ...  │
│ 关键风险：1… 2… 3…                          │
├─────────────────────────────────────────────┤
│ 模块导航（左）        模块正文（右）          │
│ 资质与主体            一句结论 + 五段式       │
│ 安全生产许可          问题卡（如有）          │
│ 人员配置与持证        待核实（如有）          │
│ 分包范围与负面清单    补正（如有）            │
│ 报审程序与合同计价                            │
│ 质量安全、工期与工资                          │
├─────────────────────────────────────────────┤
│ 附件：8 表检查表（折叠/新页）                 │
└─────────────────────────────────────────────┘
```

### 5.2 问题卡

每条问题卡四行：

```
事实：安许有效期至 2026-04-16，基准日 2026-11-17。
依据：《实施细则》附件 3 第 2 项。
影响：证照过期，不得进场。
补正：补交续期证明；责任人：分包人；期限：人工填写。
```

不再单独写“判定理由”；依据和影响就是理由。

### 5.3 模块矩阵

| 模块 | 状态 | 通过 | 不通过 | 缺项 | 待核实 |
| --- | --- | --- | --- | --- | --- |
| 资质与主体 | 通过 | 5 | 0 | 0 | 0 |
| 安全生产许可 | 不通过 | 0 | 1 | 0 | 0 |
| 人员配置与持证 | 待核实 | 4 | 0 | 1 | 2 |
| ... | ... | ... | ... | ... | ... |

矩阵放在第一页，领导 10 秒能看完；点模块下钻到段落。

## 6 V1.3 与 V1.4 的取舍

| 能力 | V1.3 | V1.4 应保留 |
| --- | --- | --- |
| 八维度矩阵 | 有 | **保留，作为 L1 模块矩阵** |
| 维度状态 | 有 | **保留，改为模块状态** |
| 问题清单 | 有，表格 | **保留，改为 L3 例外清单** |
| 函件叙述 | 弱 | **新增，按样例写** |
| 已核实事实 | 弱 | **新增，每模块一段** |
| 8 表附件 | 无 | **新增，放 L4** |
| 审批结论 | 人工 | **保留人工，不用系统建议** |

**推荐**：V1.4 = V1.3 的矩阵 + 样例的函件叙述 + 例外问题清单 + 8 表附件。不是二选一。

## 7 落地优先级

| 阶段 | 内容 | 验收 |
| --- | --- | --- |
| P0 | 恢复模块矩阵；问题表只放确证不符合/缺项；待核实单列 | 领导 10 秒能看清哪一模块有问题 |
| P0 | 每模块五段式：结论/已核实/问题/待核实/补正 | 每段能独立读懂 |
| P1 | 问题卡按 5C 写；去掉“判定理由”独立列 | 每条问题能直接补正 |
| P1 | 通过项只给数量，不逐条展开 | 报告长度下降，信息密度上升 |
| P2 | 8 表附件放附录；R4 未覆盖行折叠 | 附件不再是 20 行重复 |
| P3 | 修证照/社保/劳务资质匹配 | 已提供材料不再判缺失 |

## 9 调研来源

- 内部审计 5C 发现结构：Criteria / Condition / Cause / Consequence / Corrective action。
- 例外报告：只报例外、定义例外标准、记录根因和影响、跟踪整改。
- 合规驾驶舱：总体状态、模块覆盖、未关闭问题、证据状态、下钻。
- 国内工程检查表：检查项目 / 检查内容 / 检查结果 / 检查情况描述。
