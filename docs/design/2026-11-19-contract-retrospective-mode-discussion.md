## 推荐产品形态

同一产品中的两个任务模式，而不是复制一套系统或仅切换报告模板。

| 方面 | 准入阶段 | 合同倒查阶段 |
| --- | --- | --- |
| 目标 | 企业及分包事项能否承接、准入条件是否满足 | 已有合同文本的约定风险及上下游衔接 |
| 输入 | 现有报审资料包 | 分包合同必需，总包合同可选；合同附件与补充协议可随对应合同上传 |
| 核查 | 既有准入流程 | 单合同规范检查、内部一致性；有总包时增加双侧比对 |
| 人工步骤 | 继续既有流程 | 查看发现可选，不要求逐条确认才能出报告 |
| 报告 | 九维准入报告方向待实施 | 简短范围说明与发现摘要、证据表、核查限制 |

顶栏推荐下拉列表“核查阶段：准入阶段／合同倒查阶段”，与模型并列。模式归属任务；模型选择器当前源码写入部署默认模型，阶段绝不可照此做成全局设置。任务创建时保存模式，刷新与历史恢复按任务模式；运行后变更模式宜创建新任务，保留原结果。

首版推荐一份分包合同对应一个总包合同来源集。多附件可组成同一合同来源集，但必须明确归属、版本、附件及补充关系；不按上传先后或文件名自动拼成合同。一份总包对多份分包可作为后续扩展，不在首版静默做笛卡尔比对。

## 总包辅助文件的作用

1. 确认项目、标段、工程范围和两级合同当事人的关系。
2. 提取适用于本分包的上游要求：质量、安全、工期、环保、工资管理、计价、检测、材料设备、担保保险等。
3. 辨别业主保留、总包自行履行、可传导或分包具体承担的责任，不能把总包义务全部复制给分包。
4. 结合文件优先顺序、专用与通用条款、补充协议和例外，找到有效比较基准。
5. 为每项衔接问题提供总包、分包两侧原文定位；不存在可靠对应时记录范围限制。

总包合同是合同约定依据，不是法规范本身。总包条款本身存在歧义或上位规定问题时，不能用它证明分包必须照搬。首版推荐不对总包另做完整独立审计；影响比较基准的歧义或材料限制应明确展示。需要总包独立审查时再扩大范围。

## 推荐核查链路

上传与明确合同归属 → 逐页读取及覆盖检查 → 合同结构与条款索引 → 按时间与主体选择适用依据 → 单合同检查 → 可选总分包衔接 → 证据与结果校验 → 自动保存报告 → 查看或导出（可选纠错）。

运行中重复启动必须幂等，刷新或离开页面不能中止已受理任务；报告绑定该次输入、依据与模型身份，导出只渲染已保存内容。读取、依据或模型失败允许形成明确标注限制的部分报告；全部未执行不能显示“未发现问题”。

- 单合同检查：与适用规范的冲突、内部前后矛盾、责任边界不清、金额日期及条款引用问题、有明确适用要求的必要约定遗漏。
- 总分包比对：同对象、同义务、同范围及相容基数比较；考虑总包要求已被概括引入的情形，不因分包没有逐字重写即判遗漏。
- 依据查询区分权威规范与合同条款。检索只是召回，最终引文须来自可核验版本，具备文号、条款、原文、效力期间与来源；没有可靠依据的模型推测不能包装为不符合。
- 合同长文按章节和条款跨页保留上下文，不能仅抽首页或将全部166页一次塞进提示词。建立全合同覆盖记录，未读取与零发现分别统计。
- 技术失败、OCR不可读、依据服务不可用与业务风险分开；可报告部分结果及受限范围，但不得宣称核查完整。

## 发现与报告契约

建议区别：文本不符合、合同衔接风险、内部歧义、条件性风险、现行规则提示；无法支持为具体风险的内容进入简短范围限制，不生成大批待复核事项。上述为本模式新语义建议，不能直接篡改准入的hit/miss/undecidable含义。

采用截图8列作为业务表格骨架：项目名称、总包/分包、合同文件、合同条款位置、合同相关摘录、不符合或风险说明、依据文件、依据条款及原文摘录。事项性质及历史/现行标签可放说明列或筛选标签；对照类事项的依据文件包括总包合同，法规范另列并说明效力。

每条发现至少关联：任务与模式、材料版本、合同角色、主体、条款编号/标题、PDF物理页码、原文摘录、事实条件、风险说明、依据及适用时间。需要精确高亮时保留OCR坐标或可映射文本范围；没有坐标不伪造高亮，有页码和原文仍可定位。跨页引文分段定位，不拼成原文不存在的一句话。

少人工操作不等于隐去不确定性。证据完整的发现直接进入报告，不要求用户批准；条件不足的问题明确写“若……则存在……风险”，不可写已违法。依据或引文验证失败的候选不进入确定性问题。人工可选排除或加注并保留原结果和审计。

推荐报告不用准入“同意／附条件通过／不同意”，而以发现摘要和表格为主体。没有发现时写“本次已覆盖条款范围内未发现可列示问题”，并保留覆盖限制；不能由零发现推断合同全部合规。
