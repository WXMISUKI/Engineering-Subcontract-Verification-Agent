# V1.4 正式审查意见版式与字段设计

日期：2026-11-17。状态：**版式与字段确认稿**，未改代码。

目标：以领导提供的正式审查意见版式为唯一正文，复用 V1.3 的字段与状态口径，先定排版和每章核心关注点，再逐章填充。

---

## 0 结论先行

1. **正式意见不再出现“核查结果：不符合 X｜缺项 Y｜待补正 Z”这一行**。它信息密度低、和正文重复，移到系统报告页或附录。
2. **正式意见不再出现“模块矩阵”**。矩阵适合审查人快速扫，不适合正式函件；保留在系统页面即可。
3. **正文采用领导版式**：依据段 → 标题 → 工程/分包/内容/金额四行 → 开场句 → 6 个主题章节 → 结论 + 条件 → 签章。
4. **字段口径复用 V1.3**：`basic_information`、八维度状态、finding 事实/依据/补正；只是展示方式从“表格”改成“函件段落 + 要点列表”。
5. **专业分包与劳务分包使用不同字段名和关注点**，不能共用一套文案模板。

## 2 复用 V1.3 的字段口径

V1.3 的字段格式比较稳，正式意见直接复用，不重新造字段：

| 字段组 | V1.3 来源 | 正式意见中的位置 |
| --- | --- | --- |
| 工程名称、标段、建设单位、总包、分包单位、分包事项、范围、金额、基准日 | `basic_information` | 报告头 + 章节事实 |
| 八维度状态（符合/不符合/缺项/—） | `dimensions` | 章节结论 + 要点颜色 |
| 问题事实、依据、补正 | `issues` / `findings` | “注意”条目 |
| 读取/能力/范围限制 | `limitations`、`scope_statements` | 章节末尾“需核实”或全局边界 |
| 材料页数、报审日期 | `material_page_count`、`submitted_date` | 报告头或开场句 |
| 审批意见/签字 | `approval` | 结论 + 签章 |

**原则**：正式意见不新增一套字段，只换展示方式。V1.3 能填的，正式意见直接用；V1.3 填不了的，正式意见不硬写。

## 3 专业分包 vs 劳务分包：字段名与关注点

### 3.1 报告头字段

| 位置 | 专业分包 | 劳务分包 |
| --- | --- | --- |
| 第 2 行 | 分包单位 | 劳务单位 |
| 第 3 行 | 分包内容 | 劳务内容 |
| 第 4 行 | 分包金额 | 合同金额 |

### 3.2 章节字段差异

| 章节 | 专业分包 | 劳务分包 |
| --- | --- | --- |
| 1 资质与承接能力 | 专业承包资质类别/等级、覆盖范围、营业执照、法人、注册资本、配套资质 | 施工劳务资质（不分等级）、营业执照、法人、安全生产许可证 |
| 2 安全生产许可 | 安许证号、许可范围、有效期 | 同左 |
| 3 人员配置 | 项目经理、总工、安全员、质量员、八大员、社保、特种作业 | 项目负责人、专职安全员、劳务员、特种作业人员、社保、考勤 |
| 4 范围与负面清单 | 单位/分部/分项工程、负面清单、关键工序、再分包/转包 | 劳务作业内容、是否以劳务名义施工分包、是否计取主材款、是否自行编方案/试验检测/档案 |
| 5 合同与支付 | 分包合同、计价、计量、结算、质保金、工资专户、违约 | 劳务合作合同、劳务计价、工资支付、代发、考勤、保险 |
| 6 结论 | 原则同意/附条件/不同意 | 同左，但条件按劳务特点写 |

### 3.3 六章还是七章：我的建议

六章能覆盖“资质/安许/人员/范围/合同/结论”，但有两个五步能力没有明显落点：

- 第 1 步“材料完整性 + 签字链”在六章里没有独立位置；
- 第 5 步“内部信用与事故”在六章里没有独立位置。

建议采用**七章**：

1. 资质与承接能力（含营业执照、法人、资质、业绩、信用）
2. 安全生产许可
3. 人员配置与持证
4. 分包范围与负面清单
5. 合同与支付条款
6. 报审程序与资料补正
7. 结论与要求

如果坚持六章，则做两个合并：

- 第 1 章增加“信用与业绩”小节；
- 第 5 章改为“报审程序、合同与支付”，把材料完整性和签字链并入。

#### 五步能力到章节的映射

| 五步核查能力 | 七章落点 | 说明 |
| --- | --- | --- |
| 1 材料完整性 + 签字链 | 第 6 章 报审程序与资料补正 | 第 12 条五项材料、附件 3/4 信息表、监理/发包人审批 |
| 2 资质与内容合规 | 第 1 章 + 第 4 章 | 第 8/9/10 条资质与负面清单、第 15–17 条转包/违法分包 |
| 3 人员一致性 | 第 3 章 | 第 7 条现场机构、本单位人员、附件 3/4 人员材料 |
| 4 证照有效性 | 第 1/2/3 章 | 企业证照在 1/2 章，人员证书在 3 章 |
| 5 内部信用与事故 | 第 1 章“信用与业绩”小节 | 只有内部材料才写，没有材料不硬写 |

#### 执行顺序不等于阅读顺序

- **执行顺序**：材料完整性 → 资质/内容 → 人员 → 证照 → 信用。
- **阅读顺序**：资质 → 安许 → 人员 → 范围 → 合同 → 报审 → 结论。

报告按“读者的决策逻辑”组织，不按“系统执行管线”组织。材料完整性放在第 6 章，不是因为它不重要，而是因为它更适合作为“进场前补正条件”出现在结论前。

### 3.4 劳务分包的特殊判断

劳务分包不能套用专业分包的“资质等级匹配”逻辑。核心是：

- 施工劳务资质**不分等级**，证书载明“施工劳务不分等级”即满足；
- 重点看是否**以劳务合作名义进行施工分包**：
  - 是否计取主要建筑材料款、主要周转材料款；
  - 是否由劳务企业自行编制施工方案、试验检测、工程控制测量、档案资料、质量安全管理；
- 人员看项目负责人、专职安全员、劳务员、特种作业人员，不看“八大员”全套；
- 合同看劳务计价、工资支付、考勤、保险，不看专业分包的主体结构条款。

## 4 六章的核心关注点与写法

### 4.1 资质与承接能力

**核心关注点**：

- 资质类别、等级是否覆盖本次分包内容；
- 营业执照、法人资格是否有效；
- 安全生产许可证是否在有效期（专业分包可放本章或下一章）；
- 注册资本、配套资质、类似业绩（有材料才写）。

**写法**：

```
1. 资质与承接能力

- 分包人具备××专业承包×级资质，与××分包内容匹配，符合单位工程资质要求；
- 具备营业执照、法人资格，注册资本××，具备相应履约能力；
- 公路工程×级、市政公用×级等配套资质可覆盖××施工需要。

注意：如资质等级/范围不匹配，写“注意：……，不满足……要求，须补正”。
```

**不写**：没有材料的“业绩良好”“信用良好”；没有依据的“履约能力强”。

### 4.2 安全生产许可

**核心关注点**：

- 安许证号、许可范围；
- 有效期与核查基准日比较；
- 是否过期/临近到期；
- 是否需补交续期证明。

**写法**：

```
2. 安全生产许可

- 持有（沪）JZ安许证字〔××〕××，许可范围“建筑施工”；
- 注意：安许有效期至××年××月××日，当前报审节点已超期。分包人须补充提交续期后有效安许证，否则不得进场施工。
```

**不写**：没有证书号/有效期的“安许有效”；未核对原件的“真实有效”。

### 4.3 人员配置

**核心关注点**：

- 项目经理/项目负责人、总工/技术负责人、安全员、质量员/劳务员是否齐全；
- 证书类别与岗位是否对应（注册建造师、交安B/C、特种作业证）；
- 劳动合同、社保是否为本单位、是否连续；
- 是否常驻、更换是否需审批；
- 特种作业人员数量是否满足作业面。

**写法**：

```
3. 人员配置

- 项目机构基本齐全：项目经理××（注册建造师+交安B）、总工××（交安B+工程师）、
  专职安全员××（交安C）；
- 质量、施工、资料、材料、机械、劳务、标准员配备完整，社保清单可查（××年××—××月正常参保）；
- 注意：××社保断缴/缺交安证/未提供劳动合同，不能证明为本单位人员，须补正；
- 要求：项目经理、技术负责人、安全负责人须为本单位人员并常驻现场，未经建设单位同意不得更换。
```

**劳务分包**：把“八大员”换成“项目负责人、专职安全员、劳务员、特种作业人员”。

### 4.4 分包范围与负面清单

**核心关注点**：

- 分包内容是否落在负面清单以外；
- 是否涉及桥梁/隧道主体、关键性工作；
- 是否存在整体转包、肢解分包、再分包；
- 劳务分包是否越界（计取主材、编方案、管试验检测/档案）。

**写法**：

```
4. 分包范围与负面清单

- 桩基、基坑围护、地基处理不属于公路施工分包负面清单中“主体和关键性工作”禁止分包范围；
- 但其中涉及桥梁桩基部分，应按细则核实是否属“桥梁工程关键工序”；
  若属主体结构核心受力部位，须由总承包单位自行施工或另行专项说明；
- 严禁再分包、转包；劳务作业分包须报监理审查、建设单位备案。
```

**没有证据时**：不写“疑似转包/违法分包”；只写“本次材料未涉及/未发现”，或放到“需核实”。

### 4.5 合同与支付条款

**核心关注点**：

- 合同文本是否完整；
- 计价口径（含税/管理费/安全生产费）；
- 计量周期、进度结算、支付比例；
- 农民工工资专户、代发；
- 质量/安全/工期违约条款；
- 是否与总包合同原则一致。

**写法**：

```
5. 合同与支付条款

- 报审仅附清单合价，未附完整《分包合同》条款；
- 补报材料须包含：分包合同文本、计量周期、进度结算、
  农民工工资专用账户及支付保证措施、质量/安全/工期违约条款。
```

**没有合同文本时**：不逐条猜条款，直接写“未附完整合同，无法核对计价/支付/违约条款”。

### 4.6 结论

**核心关注点**：

- 原则同意/附条件通过/不同意；
- 条件清单（3–5 条，可执行）；
- 签章。

**写法**：

```
6. 结论

原则同意该专业分包，但附条件通过：

1. 补交有效期内的安全生产许可证；
2. 补交正式分包合同（含支付、质量、安全、农民工工资条款）；
3. 明确桥梁桩基是否涉及负面清单关键工序，出具有关说明；
4. 监理复核人员社保原件、特种作业证、设备清单后，建设单位最终签认；
5. 进场前完成合同信息表、分包审批表归档。

指挥部/建设单位（章）：××
日期：××年××月××日
```

**注意**：结论是审查主体的结论，不是系统“建议结论”。系统只提供事实和条件，结论由人工确认。

## 5 展示规则

### 5.1 正式意见只写三类内容

| 类型 | 写法 | 例子 |
| --- | --- | --- |
| 已核实且影响结论的事实 | 正常要点 | “具备地基基础一级资质，与分包内容匹配” |
| 影响进场/签约的关键问题 | “注意：……” | “安许已过期，不得进场” |
| 需要补正的条件 | “须/补报/要求” | “补交续期后安许证” |

其他内容：

- 已核实但不影响结论的，合并成一句“已核查通过：××、××”；
- 待核实/能力未覆盖，放到章节末尾“需核实”或系统页面，不占正式意见正文；
- 8 表附件放正式意见之后，作为附录。

### 5.2 段落格式

- 每章标题：`1. 资质与承接能力`（不用“二、三”混排）；
- 每条要点：`-` 开头，关键事实加粗；
- 问题：`注意：……`；
- 要求：`要求：……` 或 `须……`；
- 不写“判定理由”“规则依据”独立列；依据写在句子里或括号内；
- 不把多个字段拼成一行；报告头四行独立。

### 5.3 不写的内容

- “核查结果：不符合 X｜缺项 Y｜待补正 Z”；
- 模块矩阵；
- “报审资料包”这类内部术语；
- 没有证据的“符合/有效/良好”；
- 没有证据的“疑似转包/违法分包”；
- 重复的 OCR 提示（只保留一条汇总）。

## 7 七章 × 五步 × 业主关注 × 向量库依据

### 7.1 先澄清一个事实

《上海市公路工程施工分包管理实施细则》本身是**6 章 24 条**（总则、管理职责、分包条件、合同管理、行为管理、附则）。

我们说的“七章”是**报告正文的七个章节**，不是照搬细则章节。报告章节按“读者决策逻辑”组织，细则条款作为行内依据。

### 7.2 七章仍然成立

把五步核查、业主关注、向量库依据放到同一张表里看：

| 报告章节 | 对应五步能力 | 业主关心什么 | 主要向量库依据 | 展示方式 |
| --- | --- | --- | --- | --- |
| 1 资质与承接能力 | 第 2 步资质 + 第 4 步企业证照 + 第 5 步信用 | 能不能干、信用有没有问题 | 部办法第 8/10 条、建筑业企业资质标准、118 号文、内部信用材料 | 必写；业绩/设备/信用条件展开 |
| 2 安全生产许可 | 第 4 步证照有效性 | 安许有没有、是否过期 | 细则第 10 条、附件 3 第 2 项 | 必写 |
| 3 人员配置与持证 | 第 3 步人员 + 第 4 步人员证书 | 人是不是真的、证书对不对 | 细则第 7/10 条、附件 3/4 第 3 项 | 必写 |
| 4 分包范围与负面清单 | 第 2 步范围/转包/违法分包 | 合不合法、是否转包/违法分包 | 细则第 8/9/15–17 条、部负面清单 | 必写 |
| 5 合同与支付条款 | 合同要素能力 | 钱有没有风险、工资有没有保障 | 细则第 12 条、合同示范文本、保障农民工工资支付条例 | 必写；质量/安全/工期条款条件展开 |

### 7.3 向量库依据怎么用

不建议单独设“法规依据”一章。正确用法是：

1. **开头列主依据**：细则、部办法、负面清单、建筑市场管理条例、报审材料要求；
2. **正文行内引用**：每条“注意”句带条款坐标，例如“依据细则第 12 条、附件 3 第 3 项”；
3. **附录做条款索引**：同一文件只列一次，条款坐标保留；
4. **用冻结依据快照**：报告生成时读取当前任务已冻结的 `basis_refs`/规则坐标，不现场 RAG 检索；RAG 只用于原文核对或补引用；
5. **未取得/未核实依据**标注“参考/未取得”，不能写成“已依据”。

这样做的好处：

- 正文不会被法规原文淹没；
- 每条判断都能回指条款；
- 依据不会因为重新检索而漂移；
- 附录可审计，正文可阅读。

### 7.4 条件子节

七章不变，但第 1 章和第 5 章按需展开子节：

**第 1 章 资质与承接能力**

- 1.1 资质与营业执照（必写）
- 1.2 类似业绩（有材料才写）
- 1.3 设备与资源（吊装、桩基、隧道等需要时写）
- 1.4 信用与事故（只有内部材料才写）

**第 5 章 合同与支付条款**

- 5.1 合同文本与计价（必写）
- 5.2 计量、结算与支付（必写）
- 5.3 农民工工资专户/代发（有材料才写）
- 5.4 质量、安全、工期违约条款（有合同条款才写）

这样既覆盖业主关心的“设备、业绩、信用、工资”，又不会为了凑章节写“未核查”。

### 7.6 六章 vs 七章

- **推荐七章**：五步能力全部有落点，业主关注点全部有位置。
- **如果坚持六章**：
  - 第 1 章加“信用与业绩”小节；
  - 第 5 章改为“报审程序、合同与支付”，把材料完整性和签字链并入。
- **执行顺序不等于阅读顺序**：执行是“材料→资质→人员→证照→信用”，阅读是“资质→安许→人员→范围→合同→报审→结论”。
