| 符号 | 含义 |
| --- | --- |
| 依据强度 A | 法律/部令/规范性文件“应当/不得/禁止”，可判不符合 |

### 4.3 需要抽取的字段

名单/证书/合同/社保四侧统一字段：

- 姓名、身份证号、岗位、职称
- 证书类别、证书编号、有效期、注册单位
- 劳动合同单位、合同起止
- 社保缴费单位、缴费起止、缴费月份、险种
- 工资发放单位/流水（有则用）
- 拟进场时间、是否到岗

### 4.4 判定强度

- 可判“不符合”：社保单位与分包单位不一致（且无分支/退休例外）、关键岗位人员与分包单位无劳动合同。
- 可判“缺项”：缺岗位、缺劳动合同、缺社保记录、社保不覆盖基准日前一个月、缺特种作业工种。
- 只判“建议补正”：专业分包人数低于 DG/TJ 表、特种作业数量不足、设备数量不足。
- 只判“待核实”：身份证号缺失且同名、工程规模无法确定、证书等级模糊。

## 8 判定模型（三层）

### 8.1 判定 verdict

| 判定 | 含义 | 触发条件 |
| --- | --- | --- |
| 符合 | 材料已读、事实唯一、满足要求 | 证据齐全且一致 |
| 不符合 | 材料已读、事实唯一、违反 A/C 类要求 | 证据确凿 |
| 缺项 | 要求提交的材料/字段/签章/条款未找到 | 未上传、页面未读、字段未提取 |
| 待核实 | 材料已读、证据存在，但无法唯一确定 | 仅限 8.3 的三种原因 |
| 不适用 | 按适用范围判定，本条不适用于本分包 | 有明确范围理由 |
| 未纳入 | 任务级未启用/超出本轮范围 | 如 A1-01 默认关闭 |

### 8.2 处置与结论

处置 action：`无需处理 / 补正 / 说明 / 人工核对`

严重度 severity：`阻断 / 条件 / 提示`

结论 conclusion：

- 有阻断项 → 不同意
- 有条件项 → 原则同意，附条件通过
- 只有提示 → 同意

“建议补正”不是判定，而是 `严重度=提示 + 处置=补正`，不计入不符合/缺项，也不进入附条件。

### 8.3 待核实只允许三种原因

1. 同一字段多处冲突（两份社保单位不同、合同大小写金额不一致）。
2. 证据存在但字迹/OCR 无法辨认（证书等级模糊、签字潦草）。
3. 规范要求的事实/参数不在报审材料内且无法推导（工程规模、桥梁结构部位、作业面人数）。

每条待核实必须包含“文件 + 页码 + 冲突点/缺失参数”，否则报告生成器拒绝导出。

### 8.4 判定决策树

```text
规则声明所需证据：材料 M / 字段 F
│
├─ M 未上传 → 缺项（缺材料）＋补正
├─ M 已上传但页面未读/OCR失败
│    ├─ 定向补读成功 → 继续
│    └─ 补读仍失败 → 缺项（页面不可读）＋人工核对
├─ M 已读但 F 未提取 → 缺项（缺字段）＋补正
├─ F 已提取且唯一
│    ├─ 满足 → 符合
│    ├─ 违反 A 类 → 不符合（阻断）
│    ├─ 违反 C 类合同 → 不符合（条件）
│    └─ 低于 B 类推荐 → 符合（未达推荐配置）＋提示＋建议补正
├─ F 已提取但冲突/模糊
│    ├─ 冲突 → 待核实（说明）
│    └─ 模糊 → 待核实（人工核对）
├─ 外部参数缺失 → 待核实（说明缺参数）
├─ 适用范围不覆盖 → 不适用
└─ 任务未启用 → 未纳入
```

### 8.5 人工复核队列只放待核实

| 类型 | 去向 |
| --- | --- |
| 不符合 | 直接进补正清单 |
| 缺项 | 直接进补正清单 |
| 建议补正 | 进“管理建议”，不阻断 |
| 待核实 | 才进入人工复核队列 |
| 不适用/未纳入 | 进范围说明 |
