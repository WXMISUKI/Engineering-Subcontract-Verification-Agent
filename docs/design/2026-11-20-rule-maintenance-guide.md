# 分包核查规则维护指引

本指引用于新增、修改或退役规则时保持准入与合同倒查的责任边界。规则目录是归属与追踪索引，不是另一份规则正文。

## 新增或调整规则

1. 先判定规则属于 `admission`、`contract_retrospective` 还是共享基础设施。共享解析/检索函数不自动让业务判定规则跨模式共享。
2. 选择唯一权威内容位置：法条原文放依据库；条款坐标放依据索引；准入顺序放 `review_flow.json`；阈值/词表放领域数据文件；确定性判断放专属模块；倒查提示、候选校验和批次编排放倒查模块。
3. 修改 `data/rule_catalog.json`：登记稳定 ID、准确来源路径与符号、模式适用范围、owner、证据输入/输出、报告投影及回归测试。只登记引用，不复制规则正文。
4. 只有来源、入口、证据和报告映射均被代码与测试核实后，才将 `mapping_status` 设为 `verified`；局部已核实用 `partial`，尚待追踪用 `unverified`，不再使用的规则用 `retired` 并保留历史来源。
5. 运行规则目录测试和受影响的模块回归。先用迁移前行为作为基线，确认改动没有改变业务输出后，才删除旧兼容路径。

## 依据与报告要求

- 依据原文、依据坐标、规则适用期和业务判定分开维护；条款版本/适用日应由可信基准日边界决定。
- 报告展示是已确认结构化结果的投影。不能把目录标签、检索命中或模型候选直接升级为法律结论。
- 规则变更应检查任务规则版本/快照策略及历史报告只读边界；不得为更新规则而重算历史任务。

## 退役与迁移

- 退役先将目录条目标记 `retired`，保留原始规则、依据和历史快照所需代码；确认无活动调用和无历史反序列化依赖后，另开变更删除运行入口。
- 迁移数据/函数时先保留旧公开入口作为转发器，迁移所有调用并通过定向测试后，再在独立变更中删除转发器。
- 每次变更记录前后行为、测试命令、覆盖边界和未完成项；不得以通过单测推断完整法律/规范覆盖。
