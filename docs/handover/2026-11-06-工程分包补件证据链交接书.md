## 接续顺序和验收

1. 先核对用户阶段确认约定及当前设计，修正事实不可变、质量状态和来源模型。先写有意义的失败回归，再实现第一阶段事实的正确提取、保存、版本和正常摄取入口。对未知来源、遮挡、同名、多个证书和缺失页保守处理。
2. 在隔离 SQLite 验证上传/解析/事务/幂等/重试、旧版保留、跨任务权限；评估并在隔离 MySQL 验证迁移与并发。测试读取用户提供的单页样本时复用已有识别，避免重 OCR 原册。记录第一阶段结果并等待用户确认。
3. 用户确认后，建立人员名单、岗位、证书类别/编号的关系三态。只在可核实双侧证据充分时判冲突或一致。保留原文和材料页、避免仅凭同名归并。
4. 将受影响证据投影到 A2-05 等对应问题，支持原名单、原证书、补件多侧页级定位。核查未受影响回执继承、受影响项重新复核、历史比较和报告约束。
5. 做真实工作台及报告验收，分别测试负向模拟证书、主体冲突、遮挡、不同人员、同名歧义、类别冲突、重复补件及失败恢复。正向验收仍需要同主体、同人员、原报审册未包含且可核对的清晰交安 B 证。单一负向样本不能证明正向匹配能力。
6. 每阶段报告测试范围、失败和未验证事项；用户确认后进入下一阶段。全部阶段完成才可标记持久目标完成。
