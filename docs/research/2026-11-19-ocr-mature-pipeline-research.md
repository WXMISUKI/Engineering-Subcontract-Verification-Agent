# 合同扫描件 OCR 成熟处理方案调研

日期：2026-11-19。性质：官方资料研究与现有诊断的整理，不表示方案已经接入或验收通过。本次没有修改业务代码、调用付费模型或重跑 OCR。按用户最新方向，OCR 后续由用户另行处理，此文仅保存调研结果，不作为当前开发任务。

## 结论

透印、背面章痕和噪点通常不是合同条款的合规问题，但仍需正确识别页面类型，避免 OCR 把背景生成伪文字。**本样本不能归结为只需处理旋转页**：还有清晰正文循环生成、清晰签署页漏字，以及 HTML 表格质量判定误拦截。

成熟方案是按页面进行方向和版式处理、识别、结果校验，再对明确异常做针对性补读。原件始终保留；去噪、旋转、裁剪都产生派生输入，不能覆盖原件。确认无实质正文的扫描背面可以不做条款分析，但必须先有图像层面的分类依据；“OCR 没识别出字”不等于“原件没字”。后一句是本项目的工程建议，不是任何产品的准确率保证。

印章出现在签署页时可能属于有意义的合同证据，不能与背面残留章痕统一忽略。无需在条款报告中把噪点本身列为合同风险。

## 官方成熟能力

### 1. 现有 Qwen OCR 已有可复用能力

阿里云官方文档列出高精识别、表格解析、文档解析等内置任务；高精识别能返回文字行及定位坐标，表格解析返回 HTML 并表达合并单元格。[1]

官方说明 DashScope 接口支持图像旋转矫正和内置任务，生产建议中明确列出 `enable_rotate: true`、噪声过滤、亮度/对比度处理和避免过度压缩。这里是接口能力，**不能据此推断项目当前已经正确传参或开启功能**。需要按项目固定 SDK 版本与实际请求体核对。[1]

需要区分接口：官方“OpenAI 兼容 SDK”的通用限制部分指向 Chat 调用的高级任务限制；同页另有 `qwen3.5-ocr` 通过 Responses API 传 PDF、使用 `ocr_options.task=document_parsing` 的专门示例。不能概括成“所有 OpenAI 兼容接口都不支持内置任务”。当前文档给出的 PDF 上限为 100 MB，文档解析任务最多 50 页，其他任务最多 10 页；本合同有 76 页，不能直接视作单次整册请求可用。[1]

官方还说明：Qwen OCR 不支持自定义 System Message；指令放在 User Message；低分辨率或过小文字可能引发幻觉。自定义提示词包含完整 HTML 结构时，`qwen3.5-ocr` 可能沿用 HTML 输出，造成看似空内容或标签内容。因此正文转录、表格结构和自定义提示词必须匹配任务，不能把标签误当文字缺失。[1]

### 2. PaddleOCR 把方向、展平、文字方向和表格识别作为独立模块

PP-StructureV3 官方使用文档提供 `use_doc_orientation_classify`、`use_doc_unwarping`、`use_textline_orientation` 和 `use_table_recognition` 等独立配置，并返回文字框、识别分数、版面区域等结构结果。其示例中部分预处理默认关闭，需要按需要显式启用。[2]

这支持将“整页旋转”“曲面畸变”“文字行方向”“表格结构”分开处理，不必依赖语义大模型凭最终字符串猜方向。PaddleOCR 可作为后续本地预处理或结构化识别候选，但本次未安装、未做合同样本性能/准确率验证，不建议为了本次最小链路立即替换全部 OCR。

### 3. OCRmyPDF 明确区分转正、纠偏和清理

官方 cookbook 区分：`--rotate-pages` 处理整页方向；`--deskew` 处理轻微扫描倾斜；`--clean` 用 unpaper 清理 OCR 输入但不改变最终输出；`--clean-final` 会把清理图放入最终文件，需要逐页检查。`--remove-background` 尝试去除灰度/彩色图像的噪声背景，但可能删除有用内容或产生视觉瑕疵。其固定处理顺序为 rotate → remove background → deskew → clean。[3]

因此“先去掉全部印章或浅色痕迹”不是本项目可直接采用的默认策略。对需要清理的页面，只清理派生识别输入，并保留原始页面对照。

### 4. 成熟文档识别输出保留结构与位置

Azure Document Intelligence 的官方响应说明将全文阅读顺序、`spans`、页码及 `boundingRegions` 分开表达；表格有行列位置、合并单元格等结构。其文字和表格不是仅作为一段平铺字符串返回。[4]

这可作为数据模型参考：若要证明某表格单元格和正文引文来源，需要保留页码、区域及结构关系。该来源仅用于方案比较，不代表推荐项目迁移 Azure。

## 推荐最小增量路线（待后续授权开发）

1. **先核对现有适配器能力**：确认调用协议、固定 SDK 版本、实际旋转参数、内置任务以及结果字段；优先复用已有 Qwen OCR。
2. **页面类型与识别质量分开**：正文、横表、签署页、背面无实质正文、疑似有字但未读清分别记录。短文本阈值不能单独决定空白。
3. **只对明确异常采取补救**：第 47 页先方向校正再结构化表格；第 24 页针对重复退化分区转录；第 61 页按稀疏签署版式补读；第 69 页修正 HTML 质量统计后对照原图。无需全册重复调用大模型自证正确。
4. **保留审计**：原页、首次 OCR、派生图变换、页码、任务模式、模型/接口身份、质量原因及补读结果分别保存。新结果通过后替换当前可用投影，历史不回写。
5. **把真实未覆盖与无正文区分**：有正文但仍未恢复的页保留具体限制；没有实质正文且已确认的背面页不再当作条款分析缺口。报告中不得把“识别成功”写成“事实核实成功”。

完成条件应为：本样本 8 个背面页有分类依据；4 个有内容的异常页能对照原图核验关键文本、表格或签署字段；没有因清理而删掉浅色文字、手写、日期或印章；全部应审查批次完成后，再独立验收合同引文和依据的对应关系。上述仍是建议验收标准，当前未执行。
