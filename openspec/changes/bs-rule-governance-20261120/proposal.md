# 分包核查规则归属与维护治理

## Why

准入与合同倒查已经具备不同的运行入口和业务边界，但规则资料以流程 JSON、依据原文、坐标索引、规则清单、匹配器、专门判定器和运行提示词等多种形态存在。维护者需要先知道每种规则的权威来源、消费入口和回归测试，才能安全调整规则；历史运行副本进入 CodeGraph 后也会与当前源码产生同名符号歧义。

本变更先建立可核验的归属台账和共享边界，再定义统一登记元数据，最后只迁移一个低风险切片。它不要求把性质不同的规则正文强制合并到一种通用格式。

## What Changes

- 建立规则来源、运行入口、消费者、证据/报告落点和回归测试的映射基线。
- 明确准入与合同倒查的共享能力、模式专属能力及需要逐项验证的边界。
- 设计统一规则登记元数据与校验要求，保持规则正文按适合的数据/代码形态归属。
- 选取一个低风险规则切片试迁移，证明新登记结构能与既有运行行为兼容。
- 仅从本机 CodeGraph 索引中排除已确认的历史运行时代码副本，不改变项目规则、业务数据库或用户材料。

## Capabilities

### New Capabilities

- `bs-rule-governance`: 规则来源登记、模式归属、消费者映射和维护验收。

### Modified Capabilities

- 无。本变更前期不改变用户可见规则含义或核查结论。

## Non-goals

- 不重写 `service.py`、`router.py` 或整套规则引擎。
- 不将准入与倒查合并为一个流程，不改变历史任务、报告或规则判定。
- 不批量迁移所有 JSON，也不把提示词、依据原文、参数表和判定逻辑压成同一种规则结构。
- 不操作服务、共享数据库、部署或真实模型调用。

## Acceptance

- 每类在用规则均能从登记台账追到唯一权威来源、运行入口、证据/报告落点和维护测试；未确认项明确标注。
- CodeGraph 当前源码查询不再返回 `artifacts/bs-retrospective-trial-20261119/runtime` 的副本。
- P1 登记模型通过 OpenSpec 校验并由示例规则完整映射。
- P2 切片迁移有基线与迁移后定向回归，输出行为不变。
- P3 准入、倒查回归和维护指引记录实际命令、结果及未覆盖范围。
