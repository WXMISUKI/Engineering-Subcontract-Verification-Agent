# 报告判定配置实施计划

依据：`2026-11-11-report-policy-configuration-design.md`。用户已确认采用结构化文件，并确认新审查冻结当时规则、进行中任务保持原规则且通过受控操作采用新规则、历史报告保持原样。本计划在现有交付分支实施，不改变原工作区未提交内容。

## 文件与职责

- `backend/app/plus/blockchain_supervision/report_policy.py`：读取、严格验证策略、计算规范化内容哈希、生成/校验冻结值；不接受任意表达式或代码。
- `backend/app/plus/blockchain_supervision/report_policy_data/`：存放版本化报告策略文件，目录不位于现有 `data/*.json` 指纹范围；默认策略只包含已确认规则。
- `reference_snapshots.py`、`service.py`：在原有业务事务/审查代初始化边界冻结报告策略，保证回滚与并发一致；保持事实规则指纹及受控重跑行为。
- `reporting.py`、`report_document.py`：从任务冻结策略投影；旧任务使用明确的旧版兼容实现或旧报告快照，不能默默使用新策略；不更改人工处置和原始核查数据。
- `backend/tests/test_report_policy.py`、现有报告及版本测试：正式可维护回归。当前依据主体侧别代码在 `basis_subject_projection.py`，保持独立。

## 任务 1：策略模型与指纹隔离

进展：报告策略文件、白名单校验、规范化哈希和快照副本已实现；无已批准的基本符合规则。策略目录不参与既有 `data/*.json` 指纹；对应单元测试通过。尚未声明可支持白名单之外的新型条件。

1. 使用 JSON 和白名单模式定义 `schema_version`、`policy_id`、`version`、适用条件、映射、来源、报告结果；未确认“基本符合”的自动规则保持空。只支持本期表达所需的事实字段与比较，不允许解释字符串为代码。
2. 针对缺字段、未知字段/操作符、重复 ID、同优先级冲突、无效输出、未经确认基本符合、损坏文件编写测试；失败不得静默回退到最新版或判符合。
3. 定义规范化哈希和冻结副本；验证文件格式/换行不改变语义哈希，修改内容改变策略哈希。验证策略文件增删不改变 `knowledge_runs.rule_fingerprint()`，并对事实规则改变仍可检测做对照。不要变更现有指纹算法。
4. 验收：配置读取、校验、独立版本和隔离测试通过；不进入当前报告实际判定路径。

## 任务 2：新审查代冻结与历史兼容

进展：新审查代已在事务中冻结策略副本；真实种子回读、旧审查代副本不变、快照防篡改和无效配置不清除原指针已有测试。已新增报告规则只读比较及显式切换接口：校验审查代、原版本及目标版本，写入审计事件且不更改事实核查或材料指纹；同一审查代重新读取采用最新显式切换记录。已验证任务归属和过期请求，并通过实际 `create_review_version` 测试确认历史保存的报告及其策略在切换后不变。隔离 MySQL 8.0.46 合成并发测试发现事务旧快照可使两次请求均成功；改为任务锁内刷新 ORM 状态并对策略事件做当前读后，测试结果为一个成功、一个过期拒绝，随后定向回归 137 项通过。独立临时数据库已销毁；目标环境及更复杂故障场景仍需验证。配置管理界面仍不在第一阶段范围，当前切换只能通过接口进行。

新增证据包集成测试：真实报告构建和 ZIP 导出中，`report.json`、`opinion.json` 和切换审计事件均携带同一已冻结策略哈希；该测试使用隔离合成数据，不代表线上授权、真实业务资料或用户人工意见已验收。

版本标识：新增测试发现显式切换报告规则后，当前报告仍可能沿用旧历史版本号；现只有规则快照和审查代与该历史版本一致时才显示其版本号，否则当前投影版本号留空、独立保存规则哈希。证据包中的报告和意见书使用相同身份；历史快照不改。策略、报告、依据和版本定向回归 142 项通过。

异常处理：报告策略快照校验失败时，当前报告、意见书、PDF 和证据包接口返回可理解的 409，不生成错误结果；启动时配置无效同样返回 409。对实际启动事务的合成回归验证了回滚后任务仍为 setup、无新审查事件。另在后台准备收口处注入配置异常，确认任务回到 setup、事件明确提示报告规则配置问题而不是误称资料包损坏；报告、策略、材料内核、依据、历史接口和 ZIP 准备定向回归共 144 项通过。该测试不代表实际部署文件变更和全部异常组合已验收。

1. 在 `initialize_reference_review` 持锁及事务内冻结已校验策略副本、版本及哈希；给旧审查代和历史快照明确标记旧版兼容路径，禁止从当前策略补造历史。
2. 测试新审查代开始后策略文件更新，当前审查代仍读取原快照；新增审查代读取新版本；事务失败不留下半成品；回滚后历史仍可读取。覆盖在途并发读取和输入/授权变化时的既有门禁。
3. 本期先明确受控重算如何借用既有流程且不自动调用模型；若已有重跑链路会触发模型或写入不相干状态，先提供可验证的无副作用设计，不悄然复用。
4. 验收：快照可复现，旧版真实数据不被回填，策略更新不触发现有核查指纹漂移；完整受控重算行为必须在可复现测试中证明。

## 任务 3：配置驱动当前投影

进展：新审查代的三类证照报告判定已读取冻结策略并校验主体类型；无策略字段的旧任务暂走既有兼容逻辑。已覆盖策略篡改、不读当前文件、空策略及未确认主体；真实报告构建可读取审查代快照。其他关键点归属仍由既有代码控制，不能宣称全部映射已配置化。白名单支持三类证照及已有主体资料事实的缺件谓词；合成规则证明经确认的已支持事项可增量配置，但默认配置仍只有用户确认的三类证照，合成场景不构成真实事项批准。新型判定、自由表达式和基本符合未开放；报告、策略、证照内核、依据和历史接口共 131 项通过，前端报告 11 项通过；目标环境及真实业务验收待完成。

补充：策略条目可选声明 `effective_from` / `effective_to`，使用核查基准日按闭区间判断；指定了边界而基准日缺失或无效时不应用该规则。现有三条默认规则没有在来源不明确时臆造生效日期，沿用现有依据筛选口径；未声明日期不等于已独立证明无限期有效。同一策略内相同事项和主体的重叠配置仍直接拒绝，跨时间多版本应由已冻结的策略版本区分。策略及报告定向回归现为 133 项通过。

后续进展：现有固定要点归属已复制进冻结策略的 `bindings`，新审查代按快照映射，旧任务/旧策略兼容原映射；A2-02 企业/人员证件分类仍是固定动态逻辑，跨阶段引用和五阶段结构亦保持固定。验证器拒绝重复归属或判定规则与要点映射不一致；规则差异接口同时返回要点映射变化，旧版无法对比时明确标识。默认配置与现有清单及核查类型映射等价的合成测试、快照驱动映射变更及完整定向回归共 137 项通过。该配置只支持白名单内的映射和判据，不代表任意新核查需求都无需开发。

1. 用冻结配置驱动三类必需证照的已确认缺件规则及关键点归属；与现有实现对同一批场景逐项比对，结果、依据及说明一致。
2. 保留固定流程及数据边界：未选择为“—”；已证实不符合与未决并存时不符合并说明；读取不全、线索不确定、未确认适用性按已确认口径处理；忽略不得当作符合，采纳不伪造新的人工事实。
3. 覆盖未知主体、多个主体、历史版本、来源不可用、两侧依据不同、已处理与未处理、有关和无关 AI 覆盖、规则冲突和读取降级。无具体授权不引入“基本符合”自动场景。
4. 验收：同一任务页面、Word、PDF 采用相同冻结结果；可追溯到对应策略版本及事项；原始 finding、证据、门禁和人工回执保持独立。

## 审查重点

- 策略与核查规则两种哈希是否彻底隔离，Windows/Linux 的字节差异是否产生意外漂移。
- 冻结发生时点、事务回滚、旧任务迁移、历史快照完整性，以及配置更新期间的并发读取。
- `hit`、已确认缺件、模型建议和人工备注是否按用户确认的业务语义区分；不通过概率、低风险或计数推导基本符合。
- 一个要点中多个主体/不同来源/未决与不符合并存时，证据和判定归属是否准确。
- 配置损坏或不可用时的输出及门禁必须保守且可诊断，不得静默套用其他版本。
