# 报告判定规则结构化配置设计草案

状态：待用户审阅。用户已选择“结构化规则文件，先验证后逐步做管理界面”。本草案是该方向的具体设计，不代表已批准所有细节或已投入运行。

## 目标与边界

将报告判定中的业务事项、适用条件、证据要求、判定及依据映射从逐项硬编码迁移至可校验、可版本化的规则文件；保留五阶段、现有事实核查内核、已确认判定优先级、报告门禁与人工处置语义。外接提示词只用于事实提取及摘要辅助，不能绕过证据和规则产生判定。本阶段不建设规则管理界面，不实现自由表达式、任意代码执行，也不引入新核查范围。

已确认口径：三类必需证照在适用、无已知读取缺口且无相应信息时按缺件判不符合；有读取缺口或仅有线索时待核实。未选择显示“—”；已证实不符合与未决事项并存时显示不符合并说明未决事项。基本符合总体原则已确认，但没有任何经批准的具体自动判定场景。普通未处理事项使用系统意见，不伪造人工采纳；忽略项不进正文、不构成符合证据。

## 当前约束

- `rules.py` 已从 JSON 加载清单、规则与配置；`report_document.py` 中仍有报告要点映射及判定逻辑。`reporting.build_report` 对当前结果调用报告投影，历史版本保存独立快照。
- `reference_snapshots` 冻结审查代和依据；`knowledge_runs.rule_fingerprint()` 当前涵盖数据目录全部 JSON 和部分内核代码。若直接把报告配置加入该目录，单纯改变报告判定也可能触发既有规则漂移/AI 输入失效。必须先核对实际指纹、重跑和授权语义，不能通过新增文件意外影响现存任务。
- 已确认指纹使用文件原始字节哈希，换行符差异也会导致不同结果。此前共用附件的依据展示投影写在 `rules.py` 中，会改变该指纹；现已将展示逻辑迁出受该指纹覆盖的文件，交付分支 `rules.py` 字节恢复为当前本地原工作区对应文件及其提交版本一致。注意：隔离分支与本地原工作区仍有其他核查输入文件内容/换行差异，不能据此声称两个环境的整体指纹相同；切换运行环境前须逐项评估在途任务。
- 已确认主体类型用于区分专业/劳务的附件来源；未知或冲突不能选单侧。报告依据所用版本、原始 source 和冻结快照必须保留；不能拿新库回填旧快照。

## 建议结构

配置包含 `schema_version`、`policy_id`、版本、适用时间及规则列表。每条规则包含稳定 ID、阶段/要点、匹配的 finding 类型及事项 ID、适用主体、允许的结构化事实状态、读取及证据前提、结果、业务依据引用、确认状态和验证样例标识。枚举、布尔条件及已实现的比较操作使用白名单；未知字段、重复 ID、重叠冲突、无效版本、未经确认的基本符合配置应报错或不生效。不可执行规则正文。

示意：三类证照可分别用稳定事项 ID 与“缺件且已选/完成/无读取限制”的结构化事实匹配；判定为不符合。未知事实、依据冲突或无适用规则时不能假装符合。是否适用由任务已确认主体与清单/冻结信息决定，不以模型自由猜测。

报告引擎负责固定顺序：未选择 → “—”；成立的不符合保留并说明其他未知；影响判定的未知 → 待核实；已认可轻微瑕疵 → 基本符合；范围完整且要求均满足 → 符合。此顺序必须结合现有实际事实语义逐项验证，不改变确认稿门禁。判定摘要和人工备注仍从报告投影生成；原始 finding 与人工回执独立保存。

## 版本与历史（设计重点）

建议将**报告判定配置**版本/内容哈希与现有**事实核查规则**指纹分别记录，不能无条件塞入当前对整个 JSON 目录取哈希的路径。两者各自影响范围须以实际代码和测试核实：

1. 新审查代在开始时冻结该代使用的报告判定配置和核查依据版本；报告、意见书、页面与导出使用同一冻结输入。
2. 正在进行的任务遇配置变化时，不静默套用新配置；显示变更并要求通过已有受控流程决定使用旧版或重算投影。纯报告规则变化是否需要重跑事实核查，应以依赖明确的变更类型决定；不默认触发额外模型调用。
3. 已冻结历史报告原样读取；缺少策略快照的历史任务按既有历史投影/明确的兼容策略处理，不能用新版规则覆盖旧结果。兼容策略及确认稿门禁需要针对实际结构验证。
4. 一次生成记录规则版本、来源、匹配结果和必要的证据引用；记录不泄露秘密。回滚是切换已发布版本，不修改历史任务。

## 实施阶段和验收

1. **规格与指纹盘点**：确认配置格式、固定/可配边界、版本及历史兼容行为；用测试证明纯报告策略变更不会悄然改变正在进行的核查代。验收：可评审样例和完整依赖清单，尚未改变业务结果。
2. **加载与验证**：新增独立策略文件及白名单校验器，错误规则拒绝加载或安全降级，提供差异与版本信息；不执行外部代码。验收：合法、缺字段、冲突、未知版本及三类证照场景覆盖。
3. **投影迁移**：先迁移已确认的三类证照规则及现有要点映射，保留未获批准的基本符合场景为空；当前输出须与已确认样例一致。验收：用户确认的判定优先级、人工备注/忽略、未选择、读取限制、专业/劳务依据均通过回归。
4. **冻结和历史兼容**：在实际任务启动/生成/冻结路径接入报告策略版本，验证旧版快照、在途任务、变更重算和回滚；不改变现有确认稿门禁。验收：同一冻结任务跨配置更新可复现；不伪造人工采纳或自动重新调用模型。
5. **样本回放**：以合成数据和只读候选任务生成 Word/PDF，对照页面、分页、中文和用户认可的摘要；通过后再讨论管理界面。验收：每个已实施场景提供规则、证据、结果的可追溯记录，所有未确认业务场景明确列出。

## 待审阅的选择

建议独立报告策略版本，不把每次报告策略调整直接当成事实核查规则变化；对进行中的任务保留原策略，是否使用新策略由受控的重算动作决定。请确认该版本行为与现有任务管理习惯一致，再进入实现计划。
