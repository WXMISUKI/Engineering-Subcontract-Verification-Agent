# 五阶段关键点判定评审表（草案）

状态：供业务和专家逐项评审；本表不是已生效的自动规则或法律判断。依据当前交付分支 `report_document.py` 的 `_KEY_POINTS`、`_field_matches`、`_field_groups` 及 `review_flow.json` 整理。流程配置含历史信息，具体执行和正式依据应以实际运行结果、任务冻结版本及人工核对为准。括号中的编号仅供追踪代码，不表示已获得可用于报告的主要依据。

## 判定原则

- 已选择的关键点，以该主体、该任务实际适用范围和证据为基础；未选择显示“—”。报告应分别说明核查事实、依据及必要限制。
- 用户确认：已证实的不符合与另一项待核实同时存在，判为不符合，摘要说明未决事项。具体事实必须有足够证据；系统无法判断是否缺件时不能认定缺件。
- 用户确认：关键要求全部满足、没有影响判断的未决或阻断事项，且轻微瑕疵已查明并有明确依据确认不影响主要要求时，判为基本符合；摘要说明瑕疵。尚未批准任何具体可自动归为轻微瑕疵的事项。
- 用户确认：轻微瑕疵不设统一数量上限，按具体要点和依据判断；数量不能替代关键要求及证据完整性。
- 清单中的“关键要求”和“潜在瑕疵”均为待确认研究方向，不能据此改变规则、数据或原有报告确认门禁。人工采纳、备注、忽略与事实是否满足分开记录。

## 实际报告关键点及需审议边界

| 阶段 / 报告关键点 | 当前结果来源或关联 | 需要重点确认的适用事实与边界 | 基本符合候选 |
| --- | --- | --- | --- |
| 一 / 报审资料 | 资料清单 `RC-08` | 报审表是否属于本次要求、主体与资料包对应、必要内容及读取完整性。发现报审表不等于全部附件齐全。 | 无已批准场景。 |
| 一 / 主体资料 | `RC-A02`～`RC-A06` | 按确认的专业或劳务类型确定应提交资料；区分已证实缺件与无法识别，逐主体核对。 | 无已批准场景。 |
| 一 / 人员资料 | `RC-A07`～`RC-A09`、专业或劳务人员附件 | 判断适用人员及附件是否齐备；材料已查见不等于人员关系、资质和真实性均满足。 | 无已批准场景。 |
| 一 / 合同及清单 | `RC-A01` | 按本次适用要求核查分包合同及清单；不把可选的总包合同自动变成必需材料。 | 无已批准场景。 |
| 一 / 审批程序 | `RC-09`、`RC-A10`、`signature_chain` | 核对审批链、授权主体及签字盖章；图片检出或未检出印章不能单独证明签章有效，读取不足应说明。 | 无已批准场景。 |
| 二 / 事项定性 | 当前分包类型及范围信息的展示 | 判断分包类型、事项性质和适用要求；现有实现主要给出待核实提示，不能凭资料标签认定法律性质。 | 无已批准场景。 |
| 二 / 主体资格 | `qualification_match` / `A2-04` | 现有结果是证照文字与工程类别初步比对，不核定正式等级、规模及真实性；不能将词面匹配当作完整资质合格。 | 无已批准场景。 |
| 二 / 负面清单 | `negative_list` | 分包范围及适用清单条款、完整覆盖和证据；覆盖不明或无法关联工程内容时不能判符合。 | 无已批准场景。 |
| 二 / 再分包与挂靠 | `transfer_scope`、`illegal_subcontract` | 事实、合同范围和规则证据；提示性命中不直接定性违法，总包合同未提供时按任务范围处理。 | 无已批准场景。 |
| 二 / 审批及责任约定 | `a1_dependency` | 按具体适用条款和证据确认；不存在有依据的检查结果时不推断满足。 | 无已批准场景。 |
| 三 / 关键岗位 | 跨阶段引用 `RC-A09` | 核查人员名单及适用岗位；名单出现不等于资格、劳动关系或到岗均已满足。 | 无已批准场景。 |
| 三 / 人员与证件对应 | 跨阶段引用 `A2-05` | 核对人员与证件持有人身份的对应事实；缺证据不能按姓名相似推断。 | 无已批准场景。 |
| 三 / 劳动关系社保 | `person_consistency` | 核对对应主体、人员、合同与社保材料及适用时间；材料来源或身份无法确定时需核实。 | 无已批准场景。 |
| 三 / 特殊工种 | 跨阶段引用 `RC-P16` / `RC-L14` | 判断是否实际适用特殊工种及对应材料；未确认适用范围不能仅凭没有记录判符合。 | 无已批准场景。 |
| 四 / 企业证照有效期 | `A2-02` 可识别的企业证照 | 以核查基准日对实际证照有效期判断；聚合结果无法可靠区分企业与人员时不猜。临期按用户确认待核实。 | 无已批准场景。 |
| 四 / 人员证件有效期 | `A2-02` 可识别的人员证件 | 同上，并核对证件与具体人员；临期按用户确认待核实。 | 无已批准场景。 |

| 五 / 内部信用与事故记录 | `internal_records` / `BS-INT-01` | 以本次提供的内部材料和确定的主体为范围；缺材料或无法定位事实不能推断无记录。 | 无已批准场景。 |
| 五 / 核查范围 | 当前范围说明 | 本期只核对任务内材料，未开展外部信用渠道查询；该说明不等同外部风险判定。 | 不适用，作为范围说明。 |

## 逐条转化为自动规则前必须补齐

1. 明确适用主体、业务事实、关键要求及其来源版本；区分“适用且未完成”与“本次未选择”。
2. 对每个候选轻微瑕疵写清触发条件、排除条件、证据位置、允许该判断的业务依据和确认人；不得仅按 `severity=low`、处理率或模型文案分类。
3. 将问题事实、人工处置、后续整改及复核分开留痕；忽略不进入报告正文，但不能据忽略得出符合；未处理普通问题按照系统意见投影。
4. 统计时以主体和业务事项去重，并验证同一事项多条规则、跨阶段引用和不同主体的边界。数量只供辅助解释，不设统一阈值。
5. 验证报告、意见书、Word、PDF、冻结历史快照及确认稿阻断门禁；目前的项目数据和规则是否足以支持每一项自动判定，需逐项验证，不能用本表代替结果。
