# 设计

## 数据流

持久化 `BsTaskEvent` 是页面可读的任务进度回执；后台 Python 结构化日志是运维诊断记录。二者通过 task_id、review_run_id、job_id、request_id 关联，不把完整异常文本、模型输入或材料正文复制到用户可见事件。

后台 AI 状态接口从当前 review_run 的 job 生命周期事件和批次进度事件投影最近回执、当前组/批次、年龄及停滞候选。进度过期只代表状态需要核实，不等于失败或可安全重试。当前 job 状态不能核实时，返回 unavailable 并由页面明确展示“无法核实”。

页面的任务事件时间线仅显示白名单诊断字段。后端错误日志保留异常类型和受控失败类别，不默认记录 `str(exc)`，避免业务材料和凭据泄露。

## 兼容性

所有 API 字段均为增量可选字段；旧任务或缺字段事件投影为“无法核实”，不回填伪造进度。无需数据库迁移。
