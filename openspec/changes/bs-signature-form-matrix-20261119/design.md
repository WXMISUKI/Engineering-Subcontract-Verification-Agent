# 设计

1. signature_chains.json增加表单矩阵：附件3含项目经理、专业监理、总监、发包人；附件4仅前三者。项目经理/总监要求签字、执业章、单位盖章，专业监理要求签字，发包人要求签字及单位盖章；原文只写盖章，不猜印章形状、颜色或单位章种类。
2. 只在真实表单标题所在页识别矩阵；模板/填写示例不参与，普通合同提及附件号不触发。不同表单页各自核对，不能跨页或跨主体拼出完整表单。跨页续表暂需人工确认，不能凭通用“附件4”猜适用表单。
3. 签字栏目允许原文括号签字标识；姓名等文字只为已见文本候选。空栏/仅日期/字迹不清均不证明实际缺签，需翻原件。保留原始引文、物理页和角色。
4. seal_json的bbox只生成同页章痕迹提示，既不映射到角色，也不判章类型或缺章。材料正文写verified=true等不被消费。当前无受控角色类型核验生产者，故矩阵总结果保守待核实；确认原件可沿用现有人工复核，不另建状态机。
5. 对识别到表单的法定链A3-02-legal使用矩阵结论，集团链及未识别表单的旧兼容路径不变；证据附matrix角色与三类状态，报告展示明细消息。代码修订和数据进入规则指纹。影像角色核验与真实样本验收单列，不能因此勾满主任务6.x。
