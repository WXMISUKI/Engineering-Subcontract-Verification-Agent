## Context

倒查当前在未设任务日期时将上海当天写入 `baseline_date`，之后再从分包合同提取 `contract_date`。历史依据按 `contract_date` 选取，现行提示则按 `baseline_date` 过滤；两者来源语义因此被混用。运行身份目前要求 `baseline_date` 必须是日期字符串。现有分析已包含候选复核与最终复核，但本次真实报告证明复核没有可靠消解已明确选择、可并行的职责关系及同主体费用责任。

本变更运行于开发工作树 `feature/contract-retrospective-shared-flow`。该工作树已有未提交用户改动，实施时必须按文件核对并保留。`5174`、`8090`、`8094`、共享业务库及既有历史任务均在本变更禁止触碰范围内。

## Goals / Non-Goals

**Goals:**

- 让历史规则基准可追溯且不因默认当天而漂移。
- 修复三类已证实的合同内部语义误报，并对实质冲突保留正向检测。
- 在同一冻结输入上对照两种模型，单独记录候选验证与模型质量证据。

**Non-Goals:**

- 不建立新的人工复核工作流，不把不确定结论强行变成合规/不合规。
- 不在本阶段扩展OCR或全面重建依据库，不改写既有任务及报告。
- 不切换默认模型，不部署或重启服务，不向共享业务库写对照验收数据。

## Decisions

1. **分包合同日期是默认历史基准。** 人工明示日期优先；未指定时只接受唯一可靠的分包合同签订日。总包日期服务于合同关系和优先顺序解释，不替代被审分包合同日期。
2. **未知日期采用保守、可表达的结果。** 运行身份将审查基准标注为来源和值；若合同日期缺失/冲突且无人工日期，不用当天补值。历史规范的确定性适用判断与当前提示分开处理。若现有 `RunIdentity` 日期必填造成限制，应以向后兼容的可空/来源字段扩展契约，并为旧快照保留解析兼容。
3. **先建立确定性语义门槛，再依赖模型解释。** 对“选项已选”“要求—执行关系”“责任主体相同但费用计入合同价”等事实做结构化检查提示与抑制门槛；自动复核必须引用相关上下文。不得仅凭条款主体字面不同报告冲突。
4. **复用现有复核与检查点流程。** 不新增人工确认步骤或无上限模型链。使用既有批次/用量身份及自动复核结果；若需要额外请求，纳入冻结批次计划和费用记账。
5. **模型对照在隔离验收中执行。** 两模型读取相同的材料与依据快照，结果保存到独立证据文件，不通过运行在用候选端口或写共享业务任务进行。模型选择仍遵从任务中已冻结的配置，不在验收后自动切换默认值。

## Risks / Trade-offs

- [合同签订日期提取可能被OCR误读] → 只有明确日期标签且唯一一致才自动采用；保留原页证据和不确定限制。
- [部分旧任务缺少新的日期来源字段] → 读取旧运行身份时沿用原值并按 legacy 标记，不重新运行或回写。
- [模型仍可能将复杂法律解释误作内部冲突] → 使用三类反例及真实冲突正向样本回归；对照报告评价精确性、证据完整性和覆盖，而非只比较问题数量。
- [官方来源尚未完全核实] → P1 先修正日期逻辑；沪交行规〔2026〕8号的施行日期与适用范围在官方原件核验完成前不得固化为已证法源或自动结论。

## Migration Plan

1. 完成官方来源核验及 P1 日期契约/测试，确认旧任务兼容。
2. 完成 P1 验收后实施 P2 语义门槛及回归。
3. P2 验收后使用同一冻结输入完成 P3 模型对照，分别验证报告及导出。
4. 不修改数据库结构、历史报告或运行中的服务；回滚通过撤回本开发分支的对应代码和规格改动完成。
