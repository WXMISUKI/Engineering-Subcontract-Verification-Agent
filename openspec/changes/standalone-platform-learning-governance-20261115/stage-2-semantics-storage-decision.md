## 已确认的业务边界

用户已接受 20 条确认、13 条待确认、5 条样例不迁移，实施 4/5/13/25 + 21/24，最小报告门禁前置。此次只决定已确认业务语义的存储与兼容方式，不重新讨论该范围。

三态 `hit/miss/undecidable` 保留。普通人工提示独立表达，不能凭 `undecidable` 文案批量推断；读取、主体身份及执行失败仍保留各自状态与任务门禁。人工 accepted/ignored 只记录处置，不改材料事实或解除技术缺口。

当前独立版 `BsFinding` 无 `finding_semantics` 列；`evidence_json` 存放多侧原文证据，`review_json` 存人工回执，`discrepancy_json` 存规则/人工严重度差异，不能直接复用这些字段保存另一类含义。广场字段为可空 `String(30)`，值为 `machine_conclusion` / `manual_prompt`。D2 允许各仓本地 schema 演进，不要求同表共享。

## A 的实施约束与顺序

1. 本地模型、schema 检查/增量迁移、DTO 与快照先完成定向测试；迁移不回填、不遍历历史任务重算。线上未迁移时给明确不就绪诊断，不静默忽略列缺失。
2. 新字段仅接受 `machine_conclusion` / `manual_prompt`；NULL/未知值保守沿用旧门禁。历史快照无字段时保持缺省，不借当前 finding 补齐。
3. `manual_prompt` 只让已确认的普通提示脱离“无法核实阻断”；不改变机器 status、证据、处置权限或任务 readiness。未知身份、对象冲突、未读范围、必需运行失败不因此转普通提示。
4. 先负面清单与监理/书面同意。无信号不是未命中，候选匹配不是违法认定；表头不是签署，双侧证据分别保留原页与引用，混合态按已确认口径呈现。其他监理/同意组合不自动扩展。
5. 再逐人证件社保证据。沿用实际岗位、主体、材料修订版和页码键，避免同名即同人；岗位必需证件、月份等未确认事项继续保留。
6. 最后同页质量归组。只合并展示明确同主体/同修订材料/同物理页的质量问题，回执逐项独立；未知页和旧快照不猜测归组。

## 验收与回退

正式回归应覆盖 SQLite 持久化往返、schema 重复执行、NULL/未知语义、同代重跑回执失效、API/工作台/报告一致、历史原样读取、普通提示与技术阻断同现，以及候选发布链。MySQL 迁移/客户部署和真实材料专家验收仍需独立证据，不能以 SQLite 通过替代。

回退先停止新语义写入并恢复旧代码；已增加的可空列可保留，不以删除列销毁新数据。现有材料事实、人工回执和历史版本均不清理。B 若被选择，需在实施前补齐事件唯一性、冻结和回放规格。
