# terminal-retry

## ADDED Requirements

### Requirement: 已失败的 AI 任务可安全显式重试
系统 MUST 区分已记录失败、未开始和实际运行的工作，仅在当前审查代有效且不存在活动租约时提供同代重试。

#### Scenario: 任务失败而后续分组未启动
- **当** 后台任务明确失败、当前覆盖可确认且后续分组尚未开始
- **那么** 页面 SHALL 显示失败和可用的重试入口，不得把未开始的分组称为正在运行。

#### Scenario: 失败终态与历史停滞提示同时存在
- **当** 后台已失败且仍有过期进度回执
- **那么** 页面 SHALL 只显示一个与失败状态对应的重试入口；已完成或覆盖无法核实时 SHALL 不因过期回执额外提供入口。

#### Scenario: 有其他活动请求或状态未知
- **当** 活动租约存在、终态未知或审查代不一致
- **那么** 系统 SHALL 阻止重复启动并保留当前结果。

### Requirement: 失败后仅用户触发续跑
系统 MUST 保留当前材料和规则结果，并避免页面刷新或重新打开时自动重试已失败任务。

#### Scenario: 用户手动重试
- **当** 用户主动选择重试且服务端确认条件满足
- **那么** 系统 SHALL 在同一审查代继续，不删除已有结果，并按既有身份和版本校验复用可用批次。

#### Scenario: 同一分组中部分核查项已完成
- **当** 本次请求部分核查项已有结果而其他项需要恢复
- **那么** 系统 SHALL 使用完整请求范围重建原批次并检查匹配的检查点，仅保存待恢复核查项的结果；检查点无效时 SHALL 停止并提示。

#### Scenario: 跨进程重复提交
- **当** 同一审查代已经记录一个未有终态的后台启动
- **那么** 系统 SHALL 不因当前进程的内存中没有该任务而创建第二个后台任务。
