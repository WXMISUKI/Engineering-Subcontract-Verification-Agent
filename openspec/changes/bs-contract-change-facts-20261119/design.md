# 设计与完成条件

有限独立标题：合同变更协议/分包合同变更协议、合同补充协议/分包合同补充协议、合同变更报审表/分包变更报审表。独立附件且已读页，不把合同正文条款“应重新报审”识别为实际记录。标题与后继独立文档切段，字段从明确标签行读取并保存候选数组；原文意见可续行并保留否定/附条件，说明/模板标题不能藏在意见续行绕过排除。

前后版本是声明，不通过它们推断实质内容已比对。关联键为subject_id/project/contract_id/change_id/new_version，各字段唯一非空，审批侧同键且无身份冲突；明示前版本冲突或多值也不借审批。存在重复或可能重叠变更身份时全部保持未唯一对应；不按合同相似名称、项目同名、日期接近或仅编号部分相同借审批。未关联的审批保留独立提示，不丢负面意见。审批三方意见只列原文，日期不判程序完成或实施合法，未要求三方适用于所有类型。共享独立文档边界补变更协议/报审表及保函/保险/凭证，防方案、人员等相邻切片跨文件借字段；正文否定/义务句不当独立标题。

固定undecidable/manual_prompt，沿用signature_chain组、主体/参考代门禁及通用报告来源，不计机器问题/签署条件。change.records按新抽取器追加、旧批次不改。完成：身份版本冲突/多主体/孤立审批、否定续行、后继独立文档、模板义务/未读排除、SQLite幂等/旧批次/报告和主体门禁有正式回归；规格、版本、源码摘要及验收范围明确。
