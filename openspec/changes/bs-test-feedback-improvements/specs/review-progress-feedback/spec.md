# review-progress-feedback

## ADDED Requirements

### Requirement: 核查页面如实呈现规则与 AI 的不同阶段
页面 MUST 区分规则步骤完成和 AI 辅助核查状态，并避免将仍在执行或无法核实的 AI 覆盖显示为整步全部完成。

#### Scenario: 规则完成但 AI 仍在运行
- **当** 五步规则快照已完成且某个 AI 核查组仍在执行
- **那么** 页面 SHALL 明确表示规则已完成与 AI 进行中的区别，不得声称该步全部结束。

#### Scenario: AI 失败或状态无法核实
- **当** AI 核查失败、中断或不可核实
- **那么** 页面 SHALL 保留不确定或失败状态，不得将该阶段显示为成功。

### Requirement: 用户可通过事件时间线理解并发与失败
页面 MUST 保留时间线中的可用时间、受控的任务关联信息和失败类别，并解释并发批次回执可能乱序。

#### Scenario: 并发批次回执先后不同
- **当** 较早批次在较晚批次启动后才返回
- **那么** 页面 SHALL 按事件发生顺序显示，并说明回执可能乱序，不得将其描述为重新开始。

#### Scenario: 诊断卡片移除
- **当** 用户查看进度和失败事件
- **那么** 页面 SHALL 不展示独立执行诊断卡片，并在时间线或错误提示中保留可核实的故障信息。

### Requirement: 材料拖拽与选择使用一致的上传规则
上传页面 MUST 接受符合现有规则的 PDF/ZIP 拖入并复用现有校验和上传路径。

#### Scenario: 用户拖入有效文件
- **当** 用户向可操作的上传区域拖入有效 PDF 或 ZIP
- **那么** 系统 SHALL 按与文件选择相同的归属、校验和上传流程处理。

#### Scenario: 上传区域不可操作
- **当** 上传区域处于忙碌或只读状态
- **那么** 拖入 SHALL 不触发上传，并阻止浏览器误打开文件。

### Requirement: 报告主体类型基于可靠的主体事实
报告 MUST 正确区分用户确认的主体类别与材料识别结果；缺失或冲突 MUST 明确提示待核实。

#### Scenario: 用户确认劳务分包主体
- **当** 任务中存在已确认的劳务分包主体
- **那么** 报告对应的主体类型 SHALL 如实呈现，不得凭另一类合同材料静默改为专业分包。
