# 第一阶段验收记录（2026-11-06）

- AI 批次将明确的 HTTP 429、401/403、5xx、超时及其他错误分开归类；批次进度事件和后台失败状态保留白名单类别，工作台展示可读原因。旧事件缺少类别时沿用原文案。
- OCR 请求在明确 429 或 5xx 时最多再发一次，带随机等待；未成功的页不视为已读取，记录可信页码及错误类别。成功但质量存疑的页面没有自动重复 OCR 或旋转补读。
- 隔离 SQLite 与 FastAPI TestClient 实际上传合成扫描页、模拟 OCR 429，确认材料读取事件记录第 1 页限流；重新打开数据库后事件仍能投影。另以模拟 HTTP 测试 429 有界重试、401 不重试，测试结果及日志不包含合成密钥。
- AI 429 分类与事件投影、后台失败状态以及超时不误报 429 均有自动化测试；前端组件渲染 OCR/AI 429 的时间线信息。未实际向百炼制造限流，也未在完整独立候选镜像内通过真实浏览器注入模型错误；因此不能把组件测试称为完整浏览器验收。
- 本轮后端全量 541 passed、247 warnings；之后仅对测试文件增加重开数据库和重试场景，定向 12 passed、10 warnings。前端全量 18 passed；OpenSpec 严格校验通过。现有用户容器未重启，变更未部署或推送。
- AI SDK 自带有限重试，实际次数和时间受 SDK 与外围 120 秒总超时共同约束；本阶段没有实施跨进程/跨系统统一限流，也不能保证彻底消除 429 或超时。已完成批次按原有检查点语义保留，尚需多人负载测试评估。
