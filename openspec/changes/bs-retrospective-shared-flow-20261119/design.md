## Context

新分支feature/contract-retrospective-shared-flow基于795ca17。旧单合同真实Flash样本运行成功不代表总分包比较已实现，也不代表依据适用全部覆盖。旧方案的总包可选决定被本轮用户明确替代。

## Goals / Non-Goals

目标：复用公共三页面；新运行双合同必传；规范、内部一致性和上下游比对有真实执行及原文；免强制复核自动报告。

非目标：OCR专项、准入九维报告改造、总包独立全面审计、多分包笛卡尔比较、全仓框架重写及现有服务切换。

## Decisions

- 共享表现组件与传输工具，按模式适配启动API、readiness、进度和结果；不直接复用准入五步编排及人审门禁。
- 首版一组总包来源对应一组分包来源；关系在受理前明确，两侧输入随运行冻结。
- 总包为合同约束证据，法规范单独标识；比较同范围责任及例外，差异不自动违法。
- 历史/现行时效分开；双侧物理页和摘录可回指；原文不润色，说明专业化。
- 使用现有作业、租约、严格响应结构、检查点、用量与报告保存；不引入第二套执行框架。
- 页面显示阶段、批次及真实完成状态；事件订阅补倒查类型，恢复按run身份和sequence处理。

## Risks / Trade-offs

- 公共控制器深绑准入：先确定模式契约，只抽取实际共用部分，分阶段接入。
- 上游义务误传导：核主体/范围、有效条款与例外，强制双侧原文；检索不到不直接报遗漏。
- 新分支缺少原目录WIP：列清依赖、逐项迁移并验收，禁止全量暂存。
- 旧任务兼容：保留旧报告读取；新输入创建新运行，不复用旧单合同检查点。
- 目录隔离并非数据隔离：真实写测试前核实候选库、上传目录和端口，不连接共享业务库写测试。

## Migration Plan

先方案确认，再P1双合同受理、P2比较和双侧报告、P3公共三页面、P4真实验收。测试分层记录，不常规npm build，不变更main/5174现有运行。无需预先DDL；以现有快照契约评估实现。
