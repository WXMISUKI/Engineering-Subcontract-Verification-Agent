# 工程分包独立版：后续任务与验收方案

日期：2026-11-05。本文基于当前工作区代码、OpenSpec 和已有测试记录制定；用于后续实施，不代表正式交付或客户部署已经完成。

## 一、目标和边界

交付工程分包审查独立应用及其必要基础服务：一个交付包、一个 Compose 入口，包含分包工作台、独立账号与数据、独立 WeKnora 和必要数据库。保留五步核查、材料解析、原文定位、人工复核、补件及报告。账号只访问自己的任务；管理员创建账号；无需单位概念。

不构建智能体广场和其他完整智能体，不迁移原系统账号、业务任务、合同或日志，不修改或重启原知识库。允许将已确认属于分包智能体的资料加入离线交付，按摘要重建索引；真实密钥通过部署环境外置，不放入仓库或镜像。

“离线包”指安装所需应用与基础服务镜像及资料可离线加载；现阶段模型、OCR、Embedding 仍需配置可访问的服务，不承诺完全断网推理。客户网络和算力满足条件后再确定实际配置。

## 三、任务顺序

### P0：确认范围与交付材料清单

1. 复核源项目分包知识库实际绑定、引用包、文件清单和本地六份原件，形成“当前使用 / 历史记录 / 来源或版本待核 / 缺原件”表。现有来源访问受限时记录权限边界，不从空结果推断未使用。
2. 核对知识原件的摘要、名称、集合和文档版本；对六份中副本、负面清单版本及缺源名单明确标记。确认五步各类依据的覆盖情况，不用空文件冒充。
3. 对已迁入代码的惰性导入与业务入口做定向依赖检查，保留实际使用的共享原语；去除或明确处理指向缺失结构受力服务的旧上传入口，禁止引入其他完整智能体。

验收：资料清单可追溯到来源及摘要，缺口有明确状态；分包以外的工作台和完整智能体未进入构建。依赖：无。范围：清单、依赖审计与必要的小范围修正。

### P1：实现新环境知识初始化

1. 将现有 WeKnora 管理客户端、种子清单校验和初始化日志接入独立管理命令。输入为显式的新环境地址、管理员配置、模型配置和种子目录；不得回退至原环境地址或旧 ID。
2. 在独立环境依次创建管理员、Embedding 模型及分包知识库，按清单上传资料，轮询解析直至完成；按原件 SHA-256 记录新 KB / 文件 ID、集合、状态和模型维度。已有模型可复用时需验证身份与维度。
3. 为初始化加单实例并发控制、持久化步骤日志与原子落盘。已确认完成的步骤安全重入；超时、409、进程中断或结果不明确时先核对远端，不盲目创建或把不同文件当同一文件。日志与错误不记录密钥或正文。
4. 明确首次初始化、失败恢复、重复执行及版本升级流程；正式服务保留独立查询权限，管理凭据和应用查询凭据分离，默认不开放业务用户注册。

验收：在独立测试服务用合成文件完成创建、上传、索引、重复执行和中断恢复测试；日志、映射及密钥边界可核查。依赖：P0 清单及可用模型配置。正式资料导入在该测试通过后执行。

2026-11-05 用户确认异常恢复方向：在保证单个初始化进程和无其他人同时修改目标独立知识库的前提下，只有能只读核验远端对象身份且唯一时才恢复本地记录，无法确认时保持停止。先覆盖资料上传响应丢失：校验本地种子 SHA-256、原初始化配置指纹、已确认的目标库 ID，并完整读取目标库文件列表；仅当文件库 ID、文件名、模型和解析状态等必要信息一致且候选唯一，再只读下载远端原件复算 SHA-256 一致时恢复，继续原有解析及映射流程。WeKnora 的 `file_hash` 是 MD5，不能当成 SHA-256。列表不完整、冲突、权限不足、返回字段缺失、文件失败或没有候选均不重试上传。管理员、模型、建库及查询凭据等其他未知结果在各自身份和密钥可安全核验前继续停止，不把它们声称为已自动恢复。不得连接或修改原知识库。

### P2：建立绑定与验证五步知识链路

1. 将新环境映射、分包集合配置、知识提供方和分包绑定接入独立数据库；绑定限定目标库和文件范围，确保账户及原文下载授权仍由服务端控制。
2. 用六份已确认原件在新环境导入并核对摘要、库 ID、文件 ID 和解析状态；生成映射及导入回执，覆盖所有参考包原件。警示名单和历史案例缺失时保持不可核实，不伪造成空数据。
3. 分别验证五步知识检索、固定依据、集团补充依据和原文定位；同时覆盖无绑定、部分库失败、错密钥、模型超时和映射缺失。不得把不可用、无结果或失败当作符合。
4. 检查启动、补件、复核、重新核查及报告等所有入口的映射使用；明确缺映射时禁止启动的产品行为，与原流程三态及用户提示保持一致。

验收：五步各有查询、结果来源、文档 ID、页码及预期结果记录；用户只能读取本人任务下被授权的资料。业务结论由专家另行确认。依赖：P1。

### P3：独立业务流程与账号隔离

1. 用合成 PDF、扫描件和 ZIP 跑通创建任务、上传解析、主体确认、五步核查、人工复核、补件、报告与导出；检查页面提示及不可判定语义。
2. 审查全部任务、材料、事件、文件预览、原文和导出接口的服务端归属校验；至少使用两个账号测试直接访问、列表、下载和篡改 ID。
3. 真实配置下分别验证 LLM、OCR、Embedding 的调用、超时和失败提示；视觉印章和 OCR 定位需用代表性资料人工核对，不把合成测试视为识别质量验收。
4. 完成后再用经授权的真实业务材料在隔离环境测试；业务材料和任务数据不纳入 Git 或交付种子。专家确认业务结论、依据适用性、原文高亮和报告质量。

验收：形成完整可复现的业务流程结果、跨账号拒绝结果和异常记录；分别报告自动测试、功能流、视觉定位与专家验收。依赖：P2 可用知识链路。

### P4：启动、恢复与运维

1. 审查独立入口的启动生命周期。代码存在 `recover_interrupted_ingests`，当前未找到调用位置；需确认并接入适用的恢复机制，避免上传或准备中断后任务卡住，不能在多实例启动时误改运行中的任务。
2. 明确空库初始化、建账号、首次知识初始化、启动顺序与健康检查；`metadata.create_all` 只能创建缺失表，不是升级迁移方案，需建立版本与升级策略。
3. 设计 HTTPS / 反向代理和 Cookie 配置：目前默认本机 HTTP 监听且 Cookie 默认 Secure，不能直接按默认值宣称浏览器登录可用；测试模式和客户部署模式分别说明。
4. 分别备份、恢复并验证业务数据库、上传文件、知识数据库、知识原件及必要的稳定加密密钥；在隔离副本执行恢复演练，禁止覆盖现有生产数据。

验收：重启后数据和任务可恢复；中断状态有可理解的处理结果；备份可在新环境恢复并验证查询和文件读取。依赖：P1–P3 中相关链路。

### P5：Docker 和离线交付

2026-11-05 用户同意尝试用官方源码重建 PDF 组件：先在隔离构建环境固定并校验 PyMuPDF 1.28.0 源码包及其默认的 MuPDF 1.28.0 官方源码包，构建候选 wheel 并记录构建依赖和摘要；验证文本提取、渲染、扫描材料处理及相关回归。只有验证通过后才替换独立后端候选镜像、更新 SBOM 和源码清单，重建离线归档并在隔离环境复验；原候选保留作为回退。若构建或关键验证失败则停止替换并说明。其他第三方组件许可义务及对应源码仍需独立核查。

1. 对最终代码重新构建前后端镜像，锁定基础和第三方镜像摘要、目标 CPU 架构与版本清单；核查构建上下文和镜像层，排除密钥、账号、任务、日志及无关智能体。
2. 输出离线镜像、Compose、无密钥配置模板、知识原件与清单、初始化和安装说明、版本及 SHA-256 校验文件；估算实际压缩体积及解压/运行时磁盘与内存需求。
3. 在干净隔离环境模拟断网加载镜像并启动基础服务，配置可达模型后验证功能；测试断网与模型不可用时的提示。分别测试数据持久化和恢复，避免把联网构建当作离线安装验证。

验收：完整包可校验、导入、启动；安装和运行对网络的依赖明确，使用方能按照说明建账号并进入工作台。依赖：P1–P4。

### P6：审查、提交与验收交接

1. 审查来源代码和依赖许可证，扫描敏感信息及旧环境标识；针对公开仓库只提交授权代码、无密钥模板及必要文档，知识原件按已确认方式放离线包、不入 Git。
2. 复核源仓库和本仓库工作区，只暂存本项目文件；核实目标仓库权限与远端状态后提交、推送并回读。用户已明确仓库暂时公开，无需就同一事实重复询问。
3. 形成交付记录：版本、镜像摘要、测试与验收结果、已知限制、配置、恢复办法，以及尚需客户或专家完成的事项。客户环境部署以实际目标和授权为准。

验收：仓库提交与交付包可追溯、内容边界清楚；客户部署与业务专家验收各有单独结论。依赖：P5 及相关审核。

## 四、检查点和验证入口

- **检查点 A（P0–P1）**：资料清单可追溯；合成知识入库及失败恢复可靠，未触碰源知识服务。
- **检查点 B（P2–P3）**：五步召回及完整业务链路有证据；账号隔离、异常和不可判定语义有结果。
- **检查点 C（P4–P6）**：持久化恢复、离线加载、资料与密钥审计、仓库推送、交接记录完成。

实施时使用项目既有 Python 环境；基础回归可运行 `python -m pytest tests -q -p no:cacheprovider`（工作目录为 `backend`），前端按需要运行 `pnpm test`。Compose 用独立项目名及合成数据验证，部署级改动须对最终代码重新构建；仅在交付或关键变更需要时运行前端构建。测试文件按项目约定保留有维护价值的正式回归，清理一次性脚本和测试数据。

## 五、仍需客户侧后续提供的信息

- 目标主机的操作系统、CPU 架构、可用内存和磁盘、Docker / Compose 版本，以及是否允许访问模型和 OCR 服务。
- 正式资料中待核的版本、原件及缺失名单/案例；客户专家对业务依据、报告和视觉定位的验收结论。
- 上线访问方式（例如 HTTPS 域名或内网入口）、备份位置和运维责任人。具体部署前再按实际环境确定，不影响当前独立实现继续推进。
