## Context

源仓库当前基线为 `refactor-kbbase-luoyonglai` 的 `abb89f50`（实施前重核）；源模块任务依赖平台会话，解析依赖其他模块的公共能力。用户确认独立版不设单位，按账号隔离任务；保持三态判定并保留业务交互。独立仓库初始为空；本机 Docker Desktop 已可用。

## Goals / Non-Goals

**Goals:** 独立工作台、最小必要依赖、独立数据库与 WeKnora、单一 Compose 启动入口、可离线装载、可配置的外部模型能力。

**Non-Goals:** 迁移现有真实任务、账号、合同或日志；部署客户或生产环境；移植其他智能体完整产品；重新设计业务主流程。

## Decisions

1. 独立仓库和单一 Compose 入口，应用、持久化及 WeKnora 拆分必要服务；单镜像承载全部服务的维护风险高，不作为本次目标。
2. 先审计并迁移最小必需依赖，建立会话与认证适配；不以隐藏广场入口作为独立化证明。
3. 登录账号由交付方建立，不开放注册，不提供硬编码默认口令。不设单位，后端按任务所属账号实施访问控制。
4. 用户确认复制分包智能体实际使用的知识资料到离线包，重新建库和索引并记录文件摘要与新 ID 映射。需核实资料清单及实际文件，不复制整个混合知识库。
5. 外置模型、OCR、Embedding、Rerank 和 WeKnora 配置及密钥；离线镜像及数据卷独立，应用数据与知识服务数据分别备份。
6. 独立登录使用服务端签名的 HttpOnly Cookie，密码只存单向哈希；用户通过本地管理命令创建，接口不提供注册。保留最小会话归属模型以兼容原有分包守卫，测试使用独立内存数据库。
7. 登录后直接进入分包工作台，使用类似原平台的侧边任务列表新建及切换本人历史任务；核心工作台交互保持原样。
8. 新 WeKnora 使用独立的管理身份，初始化与业务用户认证分离；用户授权由实施方管理新知识库。重建只作用于新的隔离服务，不复用或重启原服务。外部模型凭据由环境配置注入，不写入代码或镜像。

## Risks / Trade-offs

- 平台耦合遗漏导致功能或权限失效 → 前后端、数据库、文件和模型调用逐项列出来源及验证闭环。
- 未授权资料或敏感信息泄露 → 默认排除，资料与代码分别审核，仓库及构建上下文扫描。
- 模型与向量维度不一致、页码漂移 → 记录版本及参数，验证五步召回和原文定位；不兼容时重建并复验。
- 目标架构和运行环境未确定 → 镜像架构及最低资源暂不定稿，客户环境验证单列。

## Migration Plan

在隔离环境完成依赖审计、独立入口、空库初始化、知识初始化及镜像打包；以合成材料验证功能和持久化，再在明确授权下开展真实资料与客户环境验收。升级前分别备份应用和知识数据并演练恢复；不得覆盖既有数据。
