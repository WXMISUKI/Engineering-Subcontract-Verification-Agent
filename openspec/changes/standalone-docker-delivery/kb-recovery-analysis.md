# 建库中断恢复核查（方案待确认）

2026-11-05，在新建的隔离 WeKnora v0.9.0、合成账号与合成 Embedding 服务中，创建带合成描述的测试库，核对了创建、列表和详情接口：三者均返回库名称、描述、类型、Embedding 模型 ID、视觉模型配置、空间 ID 和知识文件数；描述可保留本次指定的标识。测试环境与数据卷已删除，没有访问或修改源知识库。

实测库列表的响应包含 `success` 和 `data`，未返回 `total`、`page` 或 `page_size`。上游 [v0.9.0 处理器源码](https://github.com/Tencent/WeKnora/blob/v0.9.0/internal/handler/knowledgebase.go)显示无筛选时按当前空间列出知识库；实现时不能照搬文档文件列表的分页判断，也不能把缺失分页字段默认为完整。须以固定版本的实际 API 和代码为准，并验证调用身份和返回边界。

已有初始化日志的 `kb:` 待确认项没有操作唯一标识。库名称和模型一致即使只找到一个候选，也不能证明它是本次请求创建的；对旧记录不能自动认领或盲目重建。建议今后的新建库步骤在发请求前原子记录随机操作标识，将该标识写入新库描述，恢复时在同一独立空间只读核对标识、名称、库类型、模型和视觉配置，唯一且一致才更新日志；缺失、重复、身份不一致、列表异常或旧日志均停止人工处理。该方案需兼容现有已完成日志和文档上传恢复，修改前已向用户提出选择，尚待答复。
