## Context

现行 `bs.business-report-document.v2` 服务五阶段摘要，页面、Word 和 PDF 已共用业务文档语义。`bs.business-report.v1` 还包含八业务维度及基本信息、结论模块，但其 `available` 主要表明存在条目，不能作为八维度符合判定。旧建议函数有按三态数量生成建议的逻辑，新 V1.3 不把它当成人工审批意见。

## Confirmed Decisions

1. 双模板可选，旧版默认。
2. 收件方默认施工总承包单位／项目部；业主、分包人、收件方及出具方是独立角色。
3. 系统客观摘要与人工审批意见分开。
4. 已批准方案 A：只映射现有能力，未覆盖的八维度能力另列任务；第一版仅支持单分包主体，多主体继续使用旧模板并说明原因。
5. 人工审批意见、补正期限和三类签字在导出 Word 后填写；不开发系统内审批保存、权限流程或电子签章，无数据库迁移。

## Proposed Boundaries

- 在报告编排层增加独立模板投影，不复制规则内核，不从渲染器重跑核查。
- 模板身份 `v1.3`、外部模板版本 `V1.3`、API schema `bs.review-opinion-document.v1`、映射版本 `2026-11-16.1` 与规则／策略版本分别记录。
- 新模板读取当前所选核查代或历史快照的已有事实；历史缺少模板身份时按旧版兼容，不能从当前材料重建历史。
- 一套 V1.3 业务投影供页面、Word、PDF 消费；正文按分类输出概要，附件二按主体、问题主题和人工处置归并，成员问题 ID 留在投影中追溯。
- 维度覆盖状态独立于判定；缺项独立于判定分布；普通提示不变为机器否定认定。2026-11-16 用户修订：OCR 读取质量仅提示，真实执行缺口继续门禁，见 `bs-ocr-quality-advisory-20261116`。
- 模板身份、人工审批内容以及映射版本应纳入对应输出的内容身份。模板选择不自动触发规则策略切换。

## Data Sources

复用 `basic_information`、`materials`、`reading_coverage`、`sections`、`reference_snapshot`、`coverage`、`scope_limitations` 和既有人工作业记录。新增项目部、报送日期、事项短名、发文方及人工审批等语义不预先等同于新增数据库列。

完整字段组 H01–H19、D01–D08、I01–I12、C01–C10、X01–X06 见分析文档。字段组可以包含多个审计属性，不宣称当前 API 已实现这些路径。

## First Implementation Slice

1. `report_template_v13.build_document` 只读投影，八维度判定和覆盖分离；复用冻结策略的既有 `_point_verdict`，不新增隐式判定规则。没有完整覆盖证明时不输出维度“符合”或“基本符合”。
2. 数量使用“机器核查结果”，明确缺项可与符合／证据不足／不符合重叠。当前映射版本为 `2026-11-16.2`：有效材料页数、表格事项／范围／金额从当前材料取值；同工程格式归一，历史业绩合同不参与当前合同角色。明确报送日期缺失时省略，不借用签字、合同、上传或生成日期。
3. 报告页设置模板选择，默认 legacy。所有当前报告／意见书读取、预览及 Word／PDF 导出显式传 `template_id`；历史列表默认入口保留 legacy。模板切换使旧请求和待返回下载失效。
4. 新审查快照的 report／opinion 内冻结 `template_documents`。legacy API 返回时去掉备选文档以保持原有内容身份；选择 V1.3 时返回独立 `template_document`。旧快照没有该投影时返回 409，不用当前事实转换。
5. 页面、Word、PDF、文本预览共用冻结 blocks。模板身份、映射、事实和空白审批区纳入内容指纹；生成日期作为派生信息排除，导出时间单列。人工填写后的文件需另行留档，不冒充原系统指纹。

2026-11-16 内容修订详见 `bs-report-v13-content-refinement-20261116`。任务 7 的业主经用户确认，使用既有事件机制保存；不作为其他任务默认值。后续另确认逐主体范围、系统内审批流程及确实未载明的收件项目部等字段。

## Verification Plan

仅运行必要的正式回归与产物核验：旧默认兼容、动态字段无样例残留、八维度覆盖与判定分离、问题同源、普通提示和报告门禁、同一事实的页面/Word/PDF一致性、历史快照及人工意见身份。导出经真实渲染复核后，交业务人员确认。不运行 npm build，不调用付费模型，不重跑真实任务、不迁移数据库或部署。

## Risks And Rollback

最大风险是样例结论冒充真实认定、模块存在冒充能力覆盖、切模板污染历史。旧版始终默认，新模板独立可选；具体实现需保证未选择 V1.3 的路径不改变。历史新模板产物不能通过删除模板实现而被重解释为旧版。若需迁移数据，须在后续另列可恢复计划。
