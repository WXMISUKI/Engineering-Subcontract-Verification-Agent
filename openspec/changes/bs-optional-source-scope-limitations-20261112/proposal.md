## Why

本项目已将总包合同定义为可选材料，专业或劳务分包合同才是启动核查的硬门槛。但部分规则在缺少总包时生成 `undecidable`，另一些规则则跳过 finding 并在报告范围说明中披露，导致同一材料状态在待处理、结论和报告门禁中有不同语义。

用户已确认业务原则：总包是部分规则可能使用的补充上下文，不是分包核查的必传材料。缺少总包只限制依赖该来源的规则覆盖，不应伪装成业务 finding、符合结论或整单阻断；正式报告须如实列出未纳入本轮的规则，不能据此宣称完整通过。

## What Changes

- 建立逐规则的来源依赖矩阵，区分必需材料、可选上下文及不依赖总包的规则。
- 将来源状态、规则执行状态、三态业务 finding、范围限制提示和报告就绪状态分开建模。
- 对缺失或终态不可用的可选来源，仅将实际依赖该来源的规则标记为本轮未覆盖，并提供独立中性范围提示。
- 在人工工作区展示范围提示，但不将其作为 finding，不要求采纳/忽略，不计入 finding 数量。
- 统一报告、意见书、预览、Word/PDF、证据包及 API 的范围披露与门禁。
- 补件通过新核查代重算受影响规则；新代成功覆盖后才解除当前提示，历史快照保持不变。

## Capabilities

### New Capabilities
- `optional-source-scope-limitations`: 可选来源的规则覆盖、范围提示、报告和补件生命周期。

### Modified Capabilities
- 后续实施如需修改报告门禁或补件代际契约，应在本变更的 spec delta 中明确，不隐式扩大既有 OpenSpec 的范围。

## Impact

- 规则：`classify.py`、A1 规则内核、规则来源配置及其三态结果。
- 后端：任务/核查代覆盖投影、待办与 finding API、报告就绪门禁、补件代际和审计事件。
- 前端：待处理工作区的独立范围提示分区。
- 报告：范围说明、意见结论、预览、正式输出和导出。
- 测试：规则矩阵、API/UI、报告门禁、补件代际、历史快照和隔离端到端回归。

## Non-goals

- 不修改固定规则的实体判定标准，不将“未覆盖”算作符合或不符合。
- 不改变 AI 选页策略、MoMA provider、OCR、提示词或模型结论；AI 选页继续由 `bs-moma-ai-scope-selection` 单独管理。
- 不回写或重释历史 findings、人工决定、报告和共享任务。
- 不包含盲审、目标环境发布或生产数据迁移。

## Approval Gate

本 OpenSpec 是用户已确认原则下的需求与实施计划。本次文档确认不等于开始业务代码实现；实现阶段应在规则来源矩阵和各阶段验收门通过后启动。若需要服务端 rollout flag，应独立于 `BS_MOMA_SCOPE_SELECTOR_ENABLED`，默认关闭并按新核查代冻结。
