## Context

## Decisions

1. `review_mode=admission|contract_retrospective` 属于任务，旧值缺省为 admission；保存于既有 options JSON 并由 DTO 显式返回。所有覆盖快照路径保留模式。不得写入全局模型配置。
2. 阶段0冻结；阶段1模式纵向切片；阶段2单合同及最小自动报告/页面/导出闭环；阶段3总包辅助；阶段4综合试用验收。此顺序于2026-11-19由用户明确确认，阶段2持久目标已建立。每阶段更新验收记录并向用户汇报。
3. 只接受一个分包合同来源集和至多一个总包来源集，附件与补充协议明确归属；不可靠匹配进入范围限制。
4. 模型产出候选结构；业务层验证材料/页码/逐字摘录、依据标识/原文、时效、主体、比较关系，再进入报告。引用真实不替代适用判断；依据无可靠时效信息不得作历史不符合定性。
5. 结果类型为文本不符合、衔接风险、内部歧义、条件性风险、现行规则提示；保留时间口径。双侧比对必须双侧证据，付款比例不同不自动构成问题，工程关键词不替代工法/数量条件。
6. 报告：项目名称、总包/分包、合同文件、合同条款位置、合同相关摘录、不符合或风险说明、依据文件、依据条款及原文摘录。章节条款和PDF物理页；仅有可靠坐标才高亮。原文不可润色，说明可专业表达。
7. 后台受理与输入版本锁定；复用现有模型身份、计费和事件。前端轮询展示，不能承担运行生命周期。完成自动持久化报告；导出不调用模型；可选纠错不阻挡报告。
8. 单独记录读取、规则覆盖、模型失败、引文拒绝与未执行范围。无发现只能表述已覆盖范围；全部失败呈受限/失败，不能写无风险。
9. 总包是上游约定依据，区分业主保留、总包自行承担和分包义务，考虑文件优先级、补充协议、概括引入和例外；不机械逐字传导。

## Risks and boundaries

现有规则依据并非都具备可核验时效；不得仅凭提示词补全。扫描件 OCR 有错字和跨页条款风险，页级原文核验与明确覆盖限制并存。保持准入原门禁，不通过将 undecidable 改为 hit 来绕过人工。主业务数据库及上传卷不用于开发写测试。真实 Provider、浏览器及实际导出验收分别记录，不用模拟替代。

## Validation

隔离数据库 API 回归、前端定向测试、引文/时效/双侧反例、历史准入回归；真实文本隔离回放，必要时进行独立的真实 Provider 调用及浏览器/导出视觉检查。未执行层次明确留项。
